# 895. Maximum Frequency Stack

## 我的思考
维护两个映射和一个最大频率：

- `freqMap`：记录每个元素当前出现的频率。
- `freqStacks`：为每个频率维护一个栈，记录元素达到该频率时的入栈顺序。
- `maxFreq`：记录当前最高频率。

执行 `push(val)` 时，将元素频率加一，并把它压入对应频率的栈中，同时更新 `maxFreq`。

执行 `pop()` 时，从 `maxFreq` 对应的栈顶弹出元素。这样既保证优先弹出最高频元素，也保证频率相同时弹出最近压入的元素。若最高频率对应的栈变空，则将 `maxFreq` 减一。

## 卡点
一开始考虑使用自定义 `LinkedNode` 封装元素及其状态，但很快发现不需要支持任意位置的节点操作，按频率分组并为每个频率维护一个栈即可。

## 关键点
- 元素每次被压入时，都会在“新频率对应的栈”中留下记录。
- `freqStacks[f]` 记录的是元素达到频率 `f` 时的时间顺序，而不是当前所有频率为 `f` 的元素集合。
- 弹出最高频元素后，它在较低频率栈中的历史记录可以自然恢复其相对顺序，无须额外更新。
- 当最高频栈为空时，`maxFreq` 只需减一，因为元素频率每次只会增加或减少一层。

## 主流解对照

## 复杂度
- `push()`：平均 `O(1)`
- `pop()`：平均 `O(1)`
- 空间复杂度：`O(N)`

## 注意
- `freqMap` 中频率降为 `0` 的键可以保留，不影响后续再次插入；也可以主动删除以减少无效状态。
- `freqStacks` 中已经为空的栈可以保留并复用，无须删除。
- `freqStacks` 中的记录总数等于累计 `push()` 次数，因此总空间仍为 `O(N)`。
