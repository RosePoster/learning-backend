# 641. Design Circular Deque

## 我的思考
最初使用固定大小的双向循环链表实现。

构造时预先创建 `k + 1` 个节点，并将它们连接成环。使用 `front` 和 `rear` 两个指针在环上移动，通过额外预留一个空节点区分队列为空和队列已满：

- `front == rear` 表示队列为空。
- `front.next == rear` 表示队列已满。
- `front.prev` 是实际队首。
- `rear` 是实际队尾。

随后补充了动态链表版本。初始只创建一个节点，当现有节点全部被占用时再创建新节点。删除元素时不真正删除空闲节点，而是保留节点供后续插入复用，避免反复创建和释放对象造成额外的内存分配与 GC 压力。

最后实现了环形数组版本。数组长度设置为 `k + 1`，同样预留一个空槽区分空和满：

- `front == rear` 表示为空。
- `(front + 1) % capacity == rear` 表示已满。
- `front` 指向队首元素之后的位置。
- `rear` 指向实际队尾元素。

## 卡点
总耗时 25 分钟：

- 初版思考与实现耗时 10 分钟。
- 动态链表版和环形数组版共耗时 15 分钟。

## 关键点
环形结构中，首尾指针越过数组或链表边界后可以继续循环移动。

使用 `k + 1` 个槽位并永久预留一个空槽，可以仅通过两个指针区分空和满，而不需要额外维护元素数量。

对于固定容量的双端队列，环形数组比链表更合适：

- 所有操作均为 `O(1)`。
- 不需要运行时创建节点。
- 连续内存具有更好的 cache locality。
- 状态和实现复杂度更低。

- 构造函数：`O(k)`
- `insertFront()`：`O(1)`

- `getRear()`：`O(1)`

## 注意
需要先明确两个指针的具体语义。

动态链表版本中，不删除已经创建的空闲节点属于节点复用策略。节点数量只会增长到历史最大占用量，之后反复复用，但由于本题最大容量在构造时已经确定，最终仍优先选择环形数组实现。
