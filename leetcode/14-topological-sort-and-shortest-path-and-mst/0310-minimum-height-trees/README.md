# 310. Minimum Height Trees

## 我的思考
本题一开始没有直接想到“树中心最多只剩 1 到 2 个节点”。最开始尝试按 BFS 从外层向内遍历，并使用 `visited` 防止重复访问。

但这种普通 BFS 访问语义会污染结果。例如：

    0 - 1 - 2 - 3 - 4
            |
            5

如果从叶子层向内 BFS，短分支 `5` 会提前访问到 `2`，导致候选中心被污染，可能得到 `1、2、3` 这类错误候选。

随后想到：某个节点如果提前遇到分支，说明它不应该立刻被保留为下一层候选。于是尝试在遍历时通过 `inDegree[i] > 1` 过滤不该被保留的节点。但这种写法仍有问题：如果某个不该保留的节点排在当前遍历列表后面，前面的叶子可能先减少它的入度，导致它被错误地标记为叶子。

之后意识到，正确做法不是先获得待选节点再过滤，而是直接用 `inDegree[i] == 1` 定义当前叶子层。一个节点只有在剥掉当前整层叶子后，度数变为 1，才是下一轮叶子。

最终解法使用层层剥叶子的方式：先找到所有叶子节点，然后每轮删除当前叶子层，更新相邻节点的度数，度数变为 1 的节点进入下一轮。最后剩下的一层节点就是最小高度树的根。

当前代码使用 `nextList.isEmpty()` 作为终止条件：如果剥掉当前层后没有新的叶子层，则当前 `ans` 就是最后中心层。该写法是正规剥叶子写法的一种变体，但相比标准 `remain > 2` 写法，终止条件更隐式。

## 卡点
- 一开始把本题当成普通 BFS 向内遍历，并使用 `visited` 防重复，但普通 BFS 的“先访问”语义会被短分支污染。
- 尝试用 `inDegree[i] > 1` 对候选节点进行过滤，但过滤时机不对：当前轮内前面的叶子可能先修改后面节点的入度，导致候选判断被污染。
- 最终才收敛到：当前叶子层应该直接由 `degree == 1` 判断，而不是通过 visited 或待选过滤得到。
- 没有第一时间想到最小高度树的中心最多只剩 1 到 2 个节点，因此没有立即写出标准 `remain > 2` 版本。

## 关键点
- 本题不是普通 BFS 访问问题，而是无向树的同步剥叶子问题。
- 最小高度树的根就是树的中心点；树中心可以通过不断删除叶子得到。
- 每一轮必须同步删除当前所有叶子，不能让短分支提前访问污染结果。
- 节点进入下一轮的条件是：剥掉当前整层叶子后，`degree == 1`。
- 当前写法用 `nextList.isEmpty()` 停止，是可行变体；标准写法更推荐用 `remain > 2`，显式表达“中心最多 1 到 2 个节点”。

## 复杂度
- 时间：`O(n)`
- 空间：`O(n)`

## 注意
- 最终代码是正确的正规剥叶子变体，但前面经历了较长的 BFS/visited 误区，说明“树中心 = 层层剥叶子”的 pattern 还没有完全自动化。
