# Round 1 · Union-Find：等价连通原语的语义边界

> 类型：轮次复盘 ｜ 范围：0399 / 0547 / 0685 / 0721 / 0827 / 0839 / 0959 / 0990 / 1202 / 1319 / 1489 / 1971 / 2685（13 题）

## 摘要

标准 `find / union` 在前三四题后即稳定，本轮真正的收获不是并查集的写法，而是其表达能力的边界：UF 只能回答"两个元素是否同属一个集合"。整轮所有卡点均为同一错误的变体——让并查集承载它语义上承载不了的东西。

## 主线

### 1. UF 只建立在一维整数域上，编解码留在外部

0959 曾尝试 `int[n][n][2]` 的 parent 数组，导致 `find` 内部反复做坐标翻译、路径压缩无法保持标准写法。正确做法是所有映射在调用方完成：0959 半区压成 `i*n+j` 与 `+n*n`，0827 格子压成 `i*n+j`，0721 email 先离散化成编号。

```text
UnionFind 永远建立在一维整数域 {0..m-1} 上。
任何 (坐标 / 字符串 / 半区) -> id 的映射在调用方完成，绝不进 UF 内部。
```

价值在于 `find / union` 永远保持一行标准写法。下标翻译是限时场景最易出低级错误的环节（0827 的方向 bug：用一维 offset ±1 判左右，最左格被错映射到上一行最右格）。

### 2. 越权使用是核心失败模式

UF 维护等价关系（自反、对称、传递），超出该语义的信息硬塞必错：

- **否定关系**（0990）：`!=` 无传递性，"第二个 UF 维护不等关系"被反例 `a==b, b!=c, a==c` 打穿。不等关系只能作为集合间约束边，正解是离线两遍——先 union 全部 `==`，再扫 `!=` 检查是否同集合。
- **方向**（0685）：双入度与成环需分开处理。入度异常属方向约束，单独扫描；是否成环属连通约束，交给 UF。
- **桥 / 环上边**（1489）：结构性问题，UF 保留不了路径信息。正解为按权分批 + 连通分量压成超级节点建临时图 + Tarjan 求桥；UF 只回答"两端是否已连通"。

```text
方向、否定、桥/环、路径均不在 UF 语义内。
UF 只回答"同不同集合"，其余必须在 UF 之外建模或换工具。
```

### 3. 合法扩展：等价类的聚合摘要

附加信息若是"等价类本身的函数"，可随 union 同步维护：0827 的 `size`、2685 的 `size + edgeCount`（完全图判定 `edges == k*(k-1)/2`）、1319 的分量数（答案 `components - 1`）。边界在于：size、边数、计数只依赖"谁和谁同集合"；方向、路径、桥依赖集合内部结构，不合法。

0827 的统一化细节：水格 size 预设 0，第二遍枚举翻转时四周 root 去重累加即可，无需区分邻居类型。

### 4. 传递等价关系不能边构建边物化答案

0721 反例：`a:1,2 / a:3,4 / a:2,3` 边扫边建答案，先物化的两个 group 被后续输入再次合并，结构提前定型导致返工。纪律为两段式：

```text
阶段一 Union：只建 id、只合并；
阶段二 Collect：按最终 root 聚合、排序、补名。
```

可以边扫边分配 id、边 union，但不能边物化最终答案。0990 的离线两遍是同一纪律。

### 5. UF 几乎从不是完整算法，而是子步骤

裸跑 UF 即可结束的只有 0547 / 1971 / 1202。其余：0685 = 入度扫描 + UF 判环；1489 = 分批 Kruskal + 超级节点 + Tarjan + UF；1319 = 先判边数下界再数分量；2685 = UF + 完全图公式。解题能力体现在拆分：先切出纯连通性部分交给 UF，其余单独论证。1489 另有一条时序纪律：同权批次必须整批分类完再并入全局 UF，且临时图节点是上一批的 root——UF 的更新时机服从外层算法的语义节拍。

### 6. 实现层 invariant

union 必须 root-to-root（0990 曾把 root 挂到非 root 节点下导致 find 无限递归）：

```java
int rootI = find(i), rootJ = find(j);
if (rootI != rootJ) parent[rootJ] = rootI;
```

1-based 节点用 `n+1` 开数组、0 号弃用（0685），并区分 `nodeCount` 与数组长度。

### 7. 难度标签不是复杂度判断

0839 为 Hard 但 `n,m <= 300`，`O(n²m)` 暴力 + UF 足够；卡点来自"Hard 不该这么短"的怀疑。0399 / 0721 则是被"更聪明的变体"（lazy 缓存、在线构造）吸引拖慢主解。约束允许时，代码短、证明直接、实现风险低的解法优先。

## 规则清单

1. UF 一维整数域，编解码外置。
2. 拿到图论题先拆分：哪部分是纯等价连通（交给 UF），哪部分不是（换工具）。
3. 等价类聚合摘要（size / 边数 / 计数）可随 union 维护；集合内部结构不可。
4. 两段式：union 完再物化答案。
5. union 只做 root-to-root。
6. Hard 标签不改变复杂度判断；暴力可行时先写暴力。
