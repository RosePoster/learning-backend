# Round 6 · Math / Bit / Trick 补盲：把手工算法的中间状态显式化

> 类型：轮次复盘 ｜ 范围：0008 / 0029 / 0043 / 0050 / 0165 / 0166 / 0172 / 0273 / 0415（9 题）
> 标记：8 `[x]`、1 `[x/r]`（0166）

## 摘要

本轮是补盲轮，目标是补 0421 暴露的位运算缺口与字节字符串模拟高频题。9 题中 5 题（0008 / 0029 / 0050 / 0165 / 0415）笔记正文只有"无问题"一行，标记率 11%——**补盲目标达成，该专题无系统性缺口**，这本身是本轮的主要结论。

有实质内容的只有 4 题，收敛出一条主线：这类题的难点不在算法，而在**把手工计算过程中隐式存在的中间状态显式写成程序状态**。篇幅按材料密度控制，不作扩写。

## 主线：中间状态显式化

四题各自要显式化的状态不同，模式一致：

- **0166（长除法 → 余数即状态）**：小数部分本质是模拟长除法，判定循环节的关键是把**余数**当作状态——同一余数再次出现，之后的小数生成过程完全重复，因此循环节始于该余数第一次出现的位置，用 HashMap 记录首次位置即可。
- **0043（竖式乘法 → 贡献位即状态）**：下标 `i` 与 `j` 两位数字的乘积，个位贡献到结果的 `i + j + 1`、十位贡献到 `i + j`；长度 `n`、`m` 的两数相乘结果最多 `n + m` 位。本质是把每对数字的局部乘积累加到对应全局位置，再统一处理进位。
- **0172（因子剥离 → 规模即状态）**：末尾 0 来自 `2 × 5`，且因子 2 的数量严格多于因子 5（`i /= 5` 比 `i /= 2` 衰减更快，每步累加的 `i / 5` 也小于 `i / 2`），因此只需统计因子 5。剥离一层 5 之后，剩余问题与原问题同构、规模缩小为 `n / 5`，循环累加 `n / 5` 即可。关键是不能停在"`n / 5` 就是答案"——25、125、625 各额外贡献一层。
- **0273（三位分节 → 分节即状态）**：英文大数单位每三级提升一次（Thousand / Million / Billion），因此按三位切分 section，每个 section 独立转换后追加量词，值为 0 的 section 直接跳过以避免多余量词。

统一提问方式：**手工做这道题时，纸上真正被记住的那个量是什么**——余数、进位、当前剩余规模、当前节——那就是程序状态。

## 实现层缺口

本轮真正的耗时全部落在实现层，与 [java-api-fluency.md](java-api-fluency.md) 的横切缺口同类：

1. **映射表结构选择（0273，耗时 40min）**：最初用 HashMap，后发现连续整数到固定字符串的映射用数组更合适。规则：**连续整数查表一律用数组，不用 HashMap。**
2. **解析顺序与输出顺序相反（0273）**：主循环用 `num % 1000` 从低位向高位取 section，输出却需从高位到低位。先把各 section 存进数组、最后逆序拼接，比在头部反复插入更清晰。
3. **数组语义选择（0043）**：`char[]` 同时承担字符表示与数字位累加、进位两种职责，能正确工作但语义混杂；`int[]` 更直接，也更适合"先累计全部局部贡献、最后统一处理进位"的写法。
4. **一次性处理进位（0043）**：逐位写入时立即处理进位可行，但先累计再统一循环处理更简洁。

## 一条独立教训：相邻题目的思维惯性（0166）

0029 限制不能使用 `/` 和 `%`，惯性导致 0166 下意识开始手写十进制长除法，而本题并无此限制——直接用 `/` 取商、`%` 取余，只对小数部分模拟长除法即可。

规则：**每题起手重读一遍本题自己的约束，不要继承上一题的限制。** 这可以并入 EXECUTION.md 起手 checklist 第 1 条（圈出约束与数据范围）一并执行。

## 规则清单

1. 数值 / 字符串模拟题起手先问：手工计算时纸上被记住的量是什么，那就是程序状态。
2. 因子计数类问题剥离一层后检查是否与原问题同构，同构则循环缩小规模，不要停在第一层。
3. 连续整数到固定值的映射用数组，不用 HashMap。
4. 解析顺序与输出顺序相反时，先存分段结果再逆序拼接，不要在头部反复插入。
5. 承担数值累加职责的数组用 `int[]`，不要复用 `char[]`。
6. 每题起手重读本题约束，不继承上一题的限制。
