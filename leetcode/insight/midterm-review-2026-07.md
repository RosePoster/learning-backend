## 三、能力画像更新（相对 6-11 基线）

### 确认的强项

1. **不变量式内化不衰减**。R4 审计中二分三题（33/153/162）全部以不变量语言通过（"只和确定有序的一侧交互""删除确定不含最小值的段"）；25/124/230 等 5-8min 级通过。这条路线已被数据验证，应继续作为笔记标准。
2. **独立建模能力上限高**。0862 在不知主流解的情况下独立推导出支配关系（单调队列的一般化定义）；1368 未学过 0-1 BFS 而推出等价的 0-cost closure 解法；1489 独立完成分批 Kruskal + 超级节点 + Tarjan。上限不是问题，问题在下限的波动（见失败模式）。
3. **元认知与笔记体系**。R5 笔记已能主动核算个人变体的证明成本（0321/1944/2398 三处均自我定位"能走通但解释成本高于主流"），相比 R1 时期被变体吸引而不自知（399/721），这是可测量的进步。

### 系统性短板（仅剩两个）

**短板 1：变体辨识（算法层）**。R5 标记率 60%；具体缺口已在 round-05 收敛为可操作规则（支配关系起手、"最近 vs 最远"语义边界、枚举固定一维降维、相等元素归属先论证）。修复路径明确：R19 按重做标准消化 321/2104/862，之后规则是否内化以 UNSEEN 场次实测。

**短板 2：实现层肌肉记忆（横切层）**。跨轮反复出现且性质一致——独立于算法能力、限时环境下劣化：

| 子项 | 证据 |
|---|---|
| Java API | 297 手写 parser 28min、Deque 方法名混淆（java-api-fluency.md 已立项） |
| 位运算 | 421 思路收敛后实现耗 1h；移位/取反/最高有效位不顺手 |
| 数值表达式 | 1856 的 MOD/强转/long 反复修改 |
| 三向切分/quickselect | 324/973/912 三题均记录生疏 |
| String 操作 | 127 substring/拼接不自然 |

该短板的特点是**不会通过继续刷题自动修复**，只能靠默写制度。java-api-fluency.md 规定了"每周 5 分钟默写"，但仓库内无执行记录（无默写日志、无失分归类），制度存在、执行不可验证——建议按第六节第 4 条落地。

### 失败模式追踪（相对 6-11 基线的变化）

| 失败模式 | 6-11 状态 | 当前状态 | 趋势 |
|---|---|---|---|
| 被首个可行方案锁死 / 变体镀金 | 已识别（399/721/1334） | R4 再犯（424/103），R5 已能事后自我核算成本 | 改善中，未到"动手前拦截" |
| 脑内模拟代替纸面推导 | 未单列 | R4 集中暴露（437 等式写反、138 尾部空指针、103 方向脑补） | 新确认，修复动作明确（画图、写等式） |
| 相等元素/边界符号靠试 | 未出现 | 2104 靠试符号 AC（笔记自认）、2398 相等元素退化 O(n²) | 新确认，违反"出声讲不变量"标准 |

总体判断：失败模式清单在增长，但这是审计机制生效的表现（R4/R5 的设计目的就是暴露它们）；真正需要警惕的是"被首个方案锁死"——三轮五题以上反复出现，笔记结论正确（只能靠"写前问一句"的仪式拦截），但该仪式尚无执行载体，建议落入起手 checklist（第六节第 5 条）。

## 五、总评

体系设计的有效性在本期得到两个关键验证：审计证明了记忆路线正确（13%），R5 证明了选题机制能精准命中短板（60%）。速率风险解除后，剩余风险全部集中在三处：37 题 review 积压、UNSEEN 零执行、实现层默写制度空转。三者共同点是"无即时反馈的支线任务"，需要用与主线同等的调度刚性去执行。若第六节的调整在 R7-R8 期间落地，R9 起的 MOCK 轮将建立在干净的基础上，2027-02 投递前完成主线并具备一线大厂算法面强度的判断维持不变。

## 六、Roadmap 微调建议（待确认，未改动 ROADMAP.md）

按优先级排列。1-3 是纠偏（还债），4-6 是制度落地，7-8 是结构性微调。

### 1. R19 清单补录 + 立即启动穿插（最高优先级）

- 将新轮 24 道标记题补录进 R19：[r] 11 道（721 / 1489 / 460 / 54 / 73 / 220 / 324 / 424 / 321 / 2104 / 862），[x/r] 13 道（990 / 685 / 959 / 146 / 380 / 41 / 179 / 287 / 138 / 1856 / 1944 / 456 / 166）。
- 恢复"每 5-7 道新题穿插 1 道 review"的节奏并加严：R7-R8 期间建议 **每 2-3 道新题穿插 1 道 [r]**。R7+R8 共 15 道新题，可消化 5-7 道 [r]；剩余 [r] 在 R9 前的 UNSEEN 间隙清完。
- [r] 内部优先序：460（Design 第二批 R7 的直接前置）→ 321/2104/862（R5 重做标准已定义）→ 424 → 54/73/220/324 → 316/752/1203（旧账）→ 721/1489。
- [x/r] 中 146 会在 R9/R18 MOCK 自然重考，可不单独安排；其余分散到 R9-R11 期间作小菜。

### 2. UNSEEN 立即重启并留痕

从本周起执行"每 1-2 周一场"，并在仓库内建 `unseen/` 或在 ROADMAP 尾部加执行日志（日期 / 题号 / 结果 / 暴露盲区 → 反馈到哪个 Round）。无日志视同未执行。R9-R11 本身是 MOCK 轮，届时 UNSEEN 可降频到每 2 周一场，但不可中断——MOCK 测记忆、UNSEEN 测迁移的互补性在 R5 暴露"变体辨识短板"后价值更高了。

### 3. R7 启动前补 round-06 insight（小项）

R6 的横向收益点明确（长除法余数状态、三位分节、竖式乘法贡献位），半小时可完成，避免体例断档。

### 4. 实现层默写制度加执行载体

java-api-fluency.md 的每周默写改为**绑定固定触发点**（如每周日第一题前），并在该文件尾部追加一行式日志（日期 / 分区 / 错误数）。默写清单按 R5/R6 暴露补三个分区：位运算积木（移位、`n&-n`、`numberOfLeadingZeros`）、数值表达式（`1_000_000_007`、`(int)(ans % MOD)`、long 时机）、三向切分模板（0912 基准 + 下标版/数量版停止条件）。这是当前性价比最高的单项投入：它同时改善 R3 型实现密集题、MOCK 限时表现和笔试。

### 5. NEW/MOCK 起手 checklist 固化（一张卡片）

round-04/05 已各自沉淀规则，建议合并为四行、写入 EXECUTION.md：

```text
① 读题：圈出选择约束（连续/任意）与数据范围；
② 方案成立后动手前：哪些状态可降级（历史值/上界够不够）？个人变体的证明成本是否高于主流？
③ 写单调结构前：相等元素归谁？一边严格一边非严格，先论证再写符号；
④ 卡边界时：画结构、写等式，不信任脑内模拟。
```

### 6. 测试脚手架（R9 前完成）

MOCK 要求"自造反例、不依赖 LC 测试用例 debug"，目前无载体。一个最小 main 模板（读入构造 + 断言）即可，半天投入，R9-R11 与 R18 全程受益，同时提前适应 ACM 笔试 IO（原计划 2027-01 才开始演练，可借此自然前移）。

### 7. R12（多线程 4 题）提前穿插（可选）

这 4 题体量小、与 JUC 八股复习强耦合，适合作为 review 周的"小菜"填充，不必等到 R11 之后按序推进。若研二上学期八股复习启动，建议同步做掉。

### 8. 单调栈变体小型复审（R19 消化后）

R5 标记率 60%，虽不触发 NEW 轮扩审规则，但建议在 321/2104/862 重做通过后，从 LC 单调栈 tag 中抽 2 道未做过的变体按 UNSEEN 标准实测（可与第 2 条的 UNSEEN 场次合并），验证 round-05 规则是否真正内化，而非只完成了重做。
