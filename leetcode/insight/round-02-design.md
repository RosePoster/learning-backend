# Round 2 · Design：组合数据结构与同步不变量

> 类型：轮次复盘 ｜ 范围：0146 / 0173 / 0380 / 0460 / 0622 / 0705 / 0706（7 题）

## 摘要

本专题的统一母题：单一数据结构无法同时满足所有操作的复杂度要求，必须用多个结构互补，并维护结构间的同步不变量。高频 bug 全部同源——多结构间的同步不变量未守住，或操作顺序敏感。

## 母题：组合数据结构

| 题目 | 复杂度诉求 | 结构 A（定位） | 结构 B（顺序/随机/存储） | 桥接关系 |
|------|-----------|--------------|----------------------|---------|
| 0146 LRU | get/put O(1) | HashMap key→Node | 双向链表（使用顺序） | map.value 存节点引用 |
| 0460 LFU | get/put O(1) | HashMap key→Node | freq→双向链表桶 + minFreq | 二维：频率层 + 同频 LRU 层 |
| 0380 | insert/remove/random O(1) | HashMap val→index | ArrayList（随机下标 + 尾增删） | map.value 存下标 |
| 0622 循环队列 | 各操作 O(1) | 头尾指针 | 环形结构 | 牺牲 1 个哨兵槽区分空/满 |
| 0705/0706 | add/get 均摊 O(1) | 数组分桶 | 桶内链表（拉链法） | key % size 定位桶 |
| 0173 BST 迭代器 | next 均摊 O(1) | 栈 | 受控中序遍历 | 栈保存待回溯路径 |

专题训练的核心能力：为不同复杂度诉求挑选互补结构并保持一致。0460 的正确抽象——把 LFU 拆成频率层 + 同频 LRU 层两层——是该母题的典型表达。

## 可复用技巧

1. **HashMap 的 value 存引用 / 下标而非值**。0146 `key→Node`、0380 `val→index`，使 O(1) 定位 + O(1) 删除成为可能。
2. **节点反向冗余存储**。map 只提供 `key→node` 正向查找；凡"从结构 B 拿到元素后要回删结构 A"，元素内必须冗余存 A 的索引（0146 Node 存 key，0460 Node 存 key + freq）。
3. **尾元素覆盖删除**。不要求保序时，用末尾元素覆盖待删位置再删尾，O(n) 删除降为 O(1)（0380）。
4. **哨兵节点消除边界判断**。dummy head/tail 统一头部/中间/尾部的删除写法（0146 / 0622 / 0705）。
5. **极值增量维护**。0460 的 `minFreq` 仅在两类事件变化：最小频桶清空时自增、插入新节点时重置为 1。O(1) 维护极值的通法是靠局部事件增量更新，而非全局重算。
6. **均摊分析**。0173 每节点一生入栈/出栈各一次，n 次 next() 总成本 O(n)，均摊 O(1)（最坏单次 O(h)）。复杂度声明需主动区分"最坏单次"与"均摊"。

## 错误根因与铁律

高频 bug 同源清单：0380 覆盖后下标误写（`lastIndex` 应为 `deleteIndex`）；0380 `put` 与 `remove` 顺序写反，在 `val == lastVal` 边界把已删元素写回；0146 Node 漏存 key 导致淘汰时无法删 map；0460 中间态 `minFreq` 短暂指向空桶。

> **铁律一：任何一处增删，必须同步所有镜像结构。** 每个 public 方法结束前确认：哪些结构必须保持一致（如 `map.size() == list.size()`、`map[list[i]] == i`）。
>
> **铁律二：先建立新映射，再拆除旧映射；警惕自指边界。** 被删元素恰是被移动元素时，先 remove 再 put 会把刚删的元素救活。统一"先 put 新、后 remove 旧"。

落地手段：设计类题的 README 增设"不变量清单"栏，逐条列出操作前后必须成立的等式，把隐性约束显性化。

## 具体改进点（按性价比排序）

1. 0705 桶大小 1000（合数）与 0706 的 997（质数）不一致，统一为质数。
2. 哈希函数负数鲁棒性：模板写法 `(key % SIZE + SIZE) % SIZE`。
3. 0146 用 `map.size()` 取代独立 `len` 字段——少一个手动同步状态即少一处 bug 面。
4. 内部类封装风格统一为 `private static class` + 裸字段。
5. 0460 重构方向：`removeNode` 只负责删点与清空桶，`minFreq` 语义更新上提到 get/put/eviction 调用点。
6. 0705 `num2index(int i)` 形参改名 `key`，与 0706 `key2index` 对齐。

## 熟练度短板

- 树的迭代遍历（中序 / 前序 / 后序 + `pushLeft` 局部方法）是设计类与树类的公共基本功，需单独限时默写。
- 0460 耗时 1h，主要消耗在结构选型反复横跳。多结构题的纪律：先在纸上把每个操作映射到负责它的结构、确认复杂度全部达标，再编码。

## 规则清单

1. 写 public 方法前默念：操作结束后哪些镜像结构必须一致。
2. 先 put 新、后 remove 旧；自指边界（`val == lastVal`）单独验证。
3. 从结构 B 回删结构 A 时，检查元素内是否冗余存了 A 的索引。
4. 能用 `size()` 推导的状态不单独维护。
5. 多结构选型先画"操作 → 结构 → 复杂度"表，全绿再动手。
