# Round 3 · Advanced Array / Matrix：原地编码与选择模板

> 类型：轮次复盘 ｜ 范围：0041 / 0048 / 0054 / 0057 / 0073 / 0080 / 0086 / 0179 / 0220 / 0289 / 0324 / 0912 / 0973（13 题）

## 摘要

13 题落在两条主线：原地操作（用数组自身承载额外空间）与排序/选择模板（三向切分、quickselect、comparator 设计）。最大熟练度短板是三向切分 / quickselect，横跨 4 题且每题笔记均有记录。

## 主线 A：原地编码的三个层级

遇到 O(1) 额外空间要求时按层级套用：

| 层级 | 含义 | 题目 | 手法 |
|------|------|------|------|
| ① Element marker | 元素自身编码额外状态 | 0289 | 中间态（-1 / 2）同存旧值+新值，最后统一回写 |
| ② Dimension header | 行/列代表位标记整行整列 | 0073 | `rowFlag[i]→matrix[i][0]`、`colFlag[j]→matrix[0][j]` + 两个 boolean 兜底首行列 |
| ③ Index-as-hash | 值映射到下标，数组即哈希表 | 0041 | `值 x → 下标 x-1` 原地交换归位 |
| 旋转特例 | 元素沿固定几何轨道轮换 | 0048 | 四点轮换 |

识别判据：O(n) 时间 + O(1) 空间 + 值域与下标可映射 + 问缺失/重复 → index-as-hash；需要 rowFlag/colFlag 类标记数组 → 考虑塞进原数据代表位；新旧状态需同步演化 → 中间态编码。

## 主线 B：三向切分 / quickselect（最大短板）

- 0912：三向快排基准模板（随机 pivot + `[<][=][>]` partition）。
- 0973：quickselect 取"前 k 个"，k 是数量。
- 0324：quickselect 找"中位数"，target 是下标；切分后偶数位取小半段末尾、奇数位取大半段末尾倒序交叉。

两个反复出现的卡点：三向 partition 生疏；"k 是数量 vs target 是下标"的边界混淆。

> **铁律：quickselect 先确认找的是"第 k 个元素（下标）"还是"前 k 个元素（数量）"。**
> 下标版（0324）：命中条件 `lt <= target <= gt`。
> 数量版（0973）：命中条件 `lt <= k <= gt+1`（k 个元素对应下标 0..k-1）。

最高 ROI 动作：默写 0912 模板至不看能写，再分别推导出下标版 / 数量版停止条件。一次投入覆盖后续全部 top-k / 中位数 / 第 k 大。

## 工具箱（已掌握，归档备用）

1. **Pairwise comparator**（0179）：补位分桶有反例（830 vs 8308），根因是相对顺序取决于两数互相拼接的结果，不存在可靠的单元素 key。判据：不要问"a 的优先级是多少"，要问"a 在前更大还是 b 在前更大"（`(b+a).compareTo(a+b)`）。
2. **边界变量语义化**（0048 / 0054）：矩阵边界题统一 `top/bottom/left/right/layer`，禁止裸写 `n-layer-1`。若开始在外层补特殊元素，通常说明内层函数职责边界不清——正确反应是把退化层（单行/单列/完整圈）抽象进统一模型，而非打补丁。
3. **现成有序结构**（0220）：动态维护一组数 + 范围存在性查询 → TreeMap/TreeSet 的 `ceilingKey/floorKey`；配合定长删除做滑窗；边界运算转 `long` 防溢出。
4. **稳定分区 / 分段扫描**（0057 / 0080 / 0086）：0057 三段扫描（左/重叠合并/右）；0080 用位置关系 `nums[fast] != nums[slow-k]` 替代显式状态（可推广到最多保留 k 个）；0086 链表 stable partition。

## 错误根因（跨题）

1. **先打补丁、后抽象**：0054 漏中心点后针对用例补分支；0179 执着于构造单元素 key。遇边界/反例的第一反应应是回去修模型，而非在控制流上加分支。
2. **模板不熟导致实现慢**：三向 partition / quickselect，思路对、差肌肉记忆，靠限时默写解决。
3. **下标 / 计数映射易错**：0041 的 `值 x→下标 x-1` 与死循环规避、0048 轮换参数、0973 的 k 是数量非下标。凡涉及"值↔下标""数量↔下标"转换处，显式写一行注释标清映射方向。

## 与 Round 2 的对照

Round 2 根因是"多结构间同步不变量没守住"，Round 3 根因是"值/下标/数量的映射方向 + 模板熟练度 + 先抽象再编码的纪律"。指向同一条主干能力：**把隐性约束显性化**，并将事后归纳前置为编码前检查清单。

## 规则清单

1. O(1) 空间题按"原地编码三层级"套用。
2. quickselect 起手先写命中条件（下标版 / 数量版）。
3. 矩阵边界题强制先定义 `top/bottom/left/right`。
4. 排序题先问：是否存在可靠的单元素 key；不存在则 pairwise comparator。
5. 值↔下标转换处写注释标明映射方向。
6. 遇反例先修模型，不加补丁分支。
