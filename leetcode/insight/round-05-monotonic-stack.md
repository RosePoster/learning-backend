# Round 5 · Monotonic Stack 变体：单调结构的本质是支配关系

> 类型：轮次复盘 ｜ 范围：0321 / 0456 / 0735 / 0862 / 0901 / 1673 / 1856 / 1944 / 2104 / 2398（10 题）
> 标记：4 `[x]`（0901 / 0735 / 1673 / 2398）、3 `[x/r]`（1856 / 1944 / 0456）、3 `[r]`（0321 / 2104 / 0862）

## 摘要

本轮设计目标是补变体辨识能力（模板题 42/84/239 已过）。结果与目标吻合：模板题全部干净通过，10 题中 6 题带重做标记——变体辨识确实是真实短板，选题命中。本轮最大的可迁移收获是把单调栈从"模板"升级为"原理"：**单调结构的本质是维护支配关系、删除永不最优的状态**。0862 在不知道主流解的情况下独立推导出了这条原理本身。

## 主线一：单调结构 = 支配关系的物化

0862 的推导路径最有价值：需要"`preSum <= currSum - k` 且下标最大"的双条件查询，普通红黑树无法同时维护；继续推导发现支配关系——若 `preSum1 <= preSum2` 且 `idx1 >= idx2`，则状态 2 永不最优、可删——删除被支配状态后，TreeMap 中 `preSum` 递增 ⇒ `idx` 递增，`floorKey` 一次命中。这正是单调队列的一般化定义：主流 O(n) 解的单调队列，就是把同一支配关系用 deque 物化。

以此回看全轮：单调栈弹栈即"新元素支配栈顶"；1673 的 drop 写法即"剩余长度允许时，更大的后来者支配更小的先行者"；2398 滑窗最大值的主流解单调队列，即"更大且更新的元素支配更旧且更小的元素"。**遇到"带条件的最值查询"先问：状态之间是否存在支配关系、能否删除被支配者使剩余状态单调**——这条比任何单调栈模板都更具迁移力。

## 主线二：语义边界——单调栈只答"最近"，不答"最远"

0456 的主要耗时卡在试图用单调栈找"最远一个小于当前值"。结论应固化：单调栈稳定解决"最近更大/更小"边界，不能通过简单改造得到"最远"（反例 `[3,5,0,2,4]`）。"最远/全局"类需求换工具：左侧最小值下标用前缀最值数组一行维护。

与 Round 1（UF 只答连通）同构：工具的语义边界必须先于使用被识别，越界硬塞的成本高于换工具。

## 主线三：绑定处理是共同的死路，拆解是共同的出路

三题的初始失败方式相同——把多个角色/量绑定在同一个局部结构里在线处理：

- 2104：试图对每个子数组同时处理 max 和 min → 拆成 `sum(max 贡献) - sum(min 贡献)`，两类贡献独立用单调栈计算；
- 0456：试图同时维护 1/3/2 三个角色的位置关系 → 枚举当前值作为"2"，条件链单向展开；
- 0321：删除预算、平局比较、最优性揉在一个在线交错贪心里 → 枚举两数组取数分配，单数组最大子序列 + 固定序列字典序合并，把 `j > 0` 的平局降维成 `j = 0` 的后缀比较。

统一模式：**枚举固定一个维度（角色 / 分配 / 贡献类型），把在线的多元耦合降成离线的单元子问题**。0321 的教训另有一层：平局时真正比较的是两个子状态的最优解，在线递归展开会状态爆炸；只有先固定序列，比较才退化为可行的字典序。

## 主线四：相等元素的归属不能靠试

2104 的比较符号（`<` / `<=` 的四种组合）是靠逐一尝试 AC 的，笔记自述"问题没有真正解决，靠凑过去了"。这直接违反"出声讲不变量"标准，必须修正为论证：**同一类贡献的两侧边界必须一边严格、一边非严格，作用是给相等元素规定唯一归属，防止重复计数或漏算**（本题：max 取 left = previous greater-or-equal、right = next strictly-greater；min 对称）。规则：写单调栈前先写下相等元素归谁，再选符号。

## 主线五：实现层缺口——数值表达式与流程纪律（1856）

1856 的卡点全部在实现层：出栈定界与入栈定界两种写法中途切换；debug 与重构混做；`(int) ans % MOD` 与 `(int)(ans % MOD)` 的优先级；`10^9+7` 手写数错 0；long 使用时机临场判断。

固化三条：先用熟悉写法拿到稳定 AC，再考虑重构，两件事不同时做；`MOD` 固定写 `1_000_000_007`，取模强转固定写 `(int)(ans % MOD)`；前缀和与乘法结果无条件用 long，不在边界处临时判断。该缺口与 [java-api-fluency.md](java-api-fluency.md) 同类（实现层肌肉记忆，独立于算法能力），可并入其默写清单。

## 主线六：个人变体的成本核算（0321 / 1944 / 2398）

`nextGreater` 类个人变体本轮出现三次：0321 的预处理变体、1944 的 `nextHigher` 链版本、2398 的"nextGreater + 最大值下标"滑窗最大值。三处笔记均已自我定位：能走通、复杂度同阶，但证明与解释成本高于主流写法（0321 对标准 drop、1944 对弹栈计数、2398 对单调队列），面试默认主流。这是 Round 4 主线二（不要镀金）的正向进展——本轮已能主动核算变体的证明成本，下一步是把核算前移到动手之前。

2398 的变体另有一条独立教训：第一版沿 `nextGreater` 链维护"最大值"，`chargeTimes` 全相等时链上重复扫描退化 O(n²)——相等元素再次作祟（与主线四同源）。修正是维护"最新出现的最大值下标"，保证搜索起点全局单调右移。可迁移规则：沿链/沿指针跳跃的摊还复杂度成立，前提是搜索起点单调推进，相等元素最容易破坏这一前提。

1944 顺带沉淀一条摊还论证模板：沿链计数的总次数 = 可见关系总数 = O(n)。"担心重复遍历长链"时，先数总事件数再下结论。2398 的读题教训单独记一条：题面"连续一段"决定滑动窗口建模，读题时圈出选择约束（连续 / 任意子集）再动手，本题因此损失约 10 分钟。

## 规则清单

1. 带条件的最值查询，先找支配关系：能删除被支配状态 ⇒ 剩余状态单调 ⇒ 单调栈/队列/TreeMap 可用。
2. 单调栈只答"最近更大/更小"；"最远"类需求换前缀最值等工具。
3. 多角色/多量耦合时，枚举固定一维（角色/分配/贡献），降维成单元子问题。
4. 相等元素归属先论证再写符号：一边严格、一边非严格。
5. 先稳定 AC 再重构；debug 与优化不同时进行。
6. `1_000_000_007`、`(int)(ans % MOD)`、前缀和用 long——固定写法，不临场推。
7. 个人变体动手前先核算证明/解释成本；面试默认主流写法。
