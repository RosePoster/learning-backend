# Round 4 · 反虚假进步审计（旧 R1-R12）：衰减的不是模板，是推导链和判断力

> 类型：轮次复盘 ｜ 范围：23 题限时白板复盘 ｜ 结果：20 `[x]`、2 `[x/r]`（0287 / 0138）、1 `[r]`（0424），失败率约 13%，未触发 30% 扩审阈值

## 摘要

审计前的预设衰减模型（早期专题完成最早、衰减最重）被证伪：模板层几乎零衰减，二分、链表、回溯、树遍历全部快速通过（0025 5min、0124 6min、0230 6min）。衰减集中在两处：重建推导的能力（0287），与方案选择的判断力（0424 / 0103）。

## 主线一：记住结论 ≠ 能重建推导

0287 是唯一两个解法都未独立想起的题：值域二分没想到；快慢指针记得"从 head 和 meeting 同步走在环入口相遇"的结论，推导断在 `a + c = kb` 处，未变形出 `a = kb - c`。

失败模式：**结论的记忆寿命远长于推导的记忆寿命**。模板高频使用不衰减，结论有记忆点衰减慢，结论背后的代数变形与不变量论证最先蒸发。该题在 ROADMAP 中特别标注"双解都要讲"，衰减恰好打在"讲"上。

对机制的反馈：AUDIT 限时标准测"写不写得出"，本轮暴露的短板是"讲不讲得出为什么"。**"出声讲不变量"应从 MOCK 标准前移为 AUDIT 硬要求**，否则审计会系统性漏掉"手还会、嘴不会"的虚假存活。

0347 是轻量版同类：小根堆写出无碍，但"频率值域有限 → 下标直达替代比较排序"的识别钩子需提示才触发。

## 主线二：被第一个可行方案锁死（0424 的 [r]）

0424 的方案能走通、复杂度 O(n)、AC 无悬念，问题在维护了 `freqs + buckets` 双结构让 `maxFreq` 可真实回退，而主流解只维护历史最大值、永不回退、照样正确。检查三问：

```text
这个值是否必须真实回退？
能不能只维护历史值 / 上界 / 下界？
窗口是否必须每步严格合法，还是只要答案不被污染即可？
```

与 1334 构成完整对偶：

```text
1334：把"够用的弱状态"误当"权威的强状态"复用 → 错误（correctness bug）
0424：弱状态够用，却花大代价维护强状态 → 浪费（over-engineering）
```

完整纪律：**状态强度必须和用途匹配——不够会错，过剩会贵**。锁死发生在"已有最优复杂度方案之后"，故需显式触发时机：方案成立的那一刻、动手之前，问一遍哪些状态维护可以降级。

0103 是小号复现：双 deque + 入队顺序随方向反转，能走通但脑补费力；主流解普通 BFS + 结果层 addFirst/addLast，bug 面更小。加上 R1 的 0399/0721，该失败模式已三轮五题反复出现——不是知识缺口，是方案选择的本能偏好，只能靠"写前问一句"的仪式拦截。

## 主线三：低级错误的共性——脑内模拟冒充纸面推导

- 0437：`currSum - targetSum` 写反——等式未落纸面；
- 0138：`copyNode = copyNode.next.next` 空指针——尾部结构只存在于脑内，未画图;
- 0103：方向反转脑补费力——笔记自述"用草稿纸画会更稳"。

修复是同一个动作：画结构、写等式，不信任脑内模拟。45min 硬截止下脑内模拟出错率随压力上升，纸面推导不随。

## 主线四：API 熟练度缺口（根因修正）

0297 耗时 28min 为本轮最长，主要开销在手写 `getNum` 解析 token。需要澄清：手写 parser 并非权衡后的选择，而是 **`split` 根本没有进入候选——对 Java 标准库不熟练，默认想不到现成接口**。

同类问题反复出现：偶尔忘记 `Deque` 关键字；忘记队 / 栈的增删方法名；混淆 `put / add / offer / push / pop / poll` 等。根因一致：API 记忆依赖 IDE 补全，白板与限时环境下失效。这是独立于算法能力的缺口，需专项处理，方案见 [java-api-fluency.md](java-api-fluency.md)。

附带的面试规则仍成立：能 `split` 就 `split`，手写 parser 只在题目明确禁止时才上；序列化格式设计时就该为反序列化的解析成本让步。

## 主线五：通过的方式比通过本身更有信息量

二分三题（0033 / 0153 / 0162）通过时使用的语言全部是不变量而非模板："每轮只和确定有序的一侧交互"（0033）、"不断删除确定不含最小值的有序段"（0153）、"不分析全局形态，利用边界负无穷保证存在性"（0162）。**当初内化的若是不变量而非代码形状，就几乎不衰减**——反向印证 0287 的教训。

回溯（0046/0047/0079）、链表主干（0025/0092/0142）、树（0124/0199/0230/0235）同样干净。0047 的"同一递归层相同数值只选一次，不同层可复用"说明去重的语义边界仍在。

诚实的口子：旧 R3（堆）本轮仅 0347 一个样本且需提示，样本过小不下结论；0215 / 0295 在 R9/R10 MOCK 时应兼作堆专题补充审计。

## 收束

```text
模板几乎不衰减，衰减的是推导链（0287）和方案选择判断力（0424/0103）；
审计要测的不是"写得出吗"，而是"讲得出为什么吗"和"选得出更便宜的方案吗"。
```

执行层四条：

1. 0424 / 0287 / 0138 进 R19 消化，0424 优先；0287 重做标准是白板完整推出 `a = kb - c` 并讲出声。
2. 后续 AUDIT 一律加"出声讲不变量"标准，与 MOCK 对齐。
3. "方案成立后、动手前，问一遍状态能否降级"写进 NEW/MOCK 起手 checklist。
4. Java API 熟练度按 [java-api-fluency.md](java-api-fluency.md) 专项处理。

## 关联

三篇轮次复盘 + 1334 的元认知主线一致：1334 讲状态不能太弱，Round 1 讲工具语义不能越界，本轮讲状态不能太强、记忆不能只剩结论——同一母题的分支：**语义与用途的精确匹配**。
