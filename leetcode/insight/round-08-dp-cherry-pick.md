# Round 8 · DP cherry-pick：DP 的默认语义是全枚举，功夫在裁剪判据

> 类型：轮次复盘 ｜ 范围：0010 / 0044 / 0091 / 0097 / 0221 / 0329 / 0403（7 题）
> 标记：6 `[x]`（0221 / 0097 / 0044 / 0091 / 0329 / 0403）、1 `[x/r]`（0010）

## 摘要

本轮定位是知识扩展而非补盲——DP 经旧 R16-R19 三轮沉淀已属强项，选题只取高级变体。结果与定位一致：7 题中 6 题干净通过，标记率 14%，未暴露模板层缺口。

真正的收获不在 DP 本身，而在一个统一视角：**DP 的默认语义是"保留全部状态"，它的复杂度上界来自这个默认，而不是来自问题**。本轮七题分别从五个方向裁剪这个默认——支配、无分支、稀疏、约束剪枝、状态定义——并且 0329 提供了一个反向样本：裁剪本身也会过度。裁剪的判据由此收敛为一句可操作的话：**这条限制是否已经被别的不变量保证了**。

## 主线一：dominance 是 Round 5 主线在 DP 里的同一个概念

0044 的推导是本轮最完整的一条。pattern 按 `*` 切成固定长度块后，一个块可能在字符串中有多个合法匹配位置，直觉上需要保留全部分支。实际不需要：设存在完整可行解、其中当前块位于 `x`，而最早合法位置为 `g`，必有 `g <= x`；选 `g` 留给后续块的字符串只会更多不会更少，因此从 `x` 之后能完成的匹配，从 `g` 之后仍有机会完成。**更晚的匹配位置全部被最早位置支配，不必保存。**

这与 [Round 5](round-05-monotonic-stack.md) 主线一是同一命题的两种载体：单调栈用 deque 把支配关系物化成结构，DP 里的 greedy 用支配关系直接删掉状态维度。0044 笔记中的自我表述已经点到——"DP 会保留所有 `(sPrefix, pPrefix)` 状态，而 greedy 利用 dominance 直接删除大量没有必要的分支"。

可迁移的提问方式统一为：**两个状态之间是否存在"一个在任何未来下都不劣于另一个"的关系**。存在则被支配者可删；能删到只剩单调序列，就换单调结构；能删到只剩一个，就退化成 greedy。

## 主线二：分支才是 DP 的成本来源，无分支区间不需要 DP

0097 把这一点做成了可执行的算法。三指针扫描 `s1` / `s2` / `s3` 时，只有 `s1[i] == s2[j] == s3[i+j]` 才产生真正的分支；其余位置的选择是被迫的。标准 DP 无条件计算整个 `n × m` 状态空间，但像 `s1 = "abcd"`、`s2 = "eeee"`、`s3 = "abcdeeee"` 这样的输入全程无分支，`O(n + m)` 即可。于是：唯一合法选择时 forced transition，两边都能匹配时进入 DP，DP 完整算一行后统计 reachable 状态数，整行只剩一个 `true` 就退回 forced phase。

这里的关键是**退出条件的正确性论证**，而不是想法本身：整行只有一个 reachable state，意味着任何能到终点的合法路径都必须经过这个唯一状态，此前的分支历史因此失去意义——**一行唯一可达态构成一个 cut**。附带一条实现层推论：因为"只在整行唯一 `true` 时退出"且 `s2Idx` 单调不减，右侧旧状态不会污染后续计算，多次进入 DP 无需 `Arrays.fill`。

0091 是同一思路的轻量版：`0` 没有独立解码能力，只能作为 `10` / `20` 的后半部分，因此提前观察下一位是否为 `0`，可以剪掉那些会被后续 `0` 淘汰的路径——用题目约束在状态生成前就杀死必死分支，而不是生成后再判非法。

## 主线三：状态空间的形状比状态转移式更值得先想

0403 的核心不是转移方程，而是意识到状态不能是"是否到达石头 i"。`k ± 1` 的规则决定了下一跳依赖当前跳跃长度，只记可达性会丢失后续跳跃信息，因此状态必须是二维的 `石头位置 -> 可达跳跃长度集合`。而这个二维状态空间是稀疏的——用"位置 → 跳跃长度集合"的映射表达，比铺满 `n × n` 的表小得多。处理完的石头状态即时删除，是同一判断的空间侧推论。

0221 从反方向印证了状态定义的决定性。初版思路是"如何构造一个正方形"，需要判断区域是否闭合、能否向左向下扩展，状态难以维护；转成"以 `(i,j)` 为右下角的最大正方形边长"后，转移退化成一行 `dp[i][j] = min(左, 上, 左上) + 1`。笔记自述的卡点正是"没有第一时间想到 DP，因为思考方向偏向构造正方形，而不是以某个位置作为结尾的最大状态"。

**规则：二维结构类问题先固定"以某位置为结尾/右下角"的状态定义，再推转移；不要从"如何构造目标结构"入手。**

## 主线四：反向样本——冗余裁剪（0329）

0329 的初版给记忆化 DFS 额外加了两层状态：`-2` 标记非起点、`-1` 标记正在访问以防环，外加一个 `check` 用来筛选全局起点。三项优化全部是多余的：

- 任意节点都可以作为 DFS 起点，是否为起点不影响记忆化的正确性；
- memo 已保证每个节点最多完整计算一次；
- 严格递增条件天然排除环，不存在需要防的环。

代价是渐进复杂度没有下降，状态复杂度反而上升。这是本轮唯一的负向样本，也是把主线一到三的判据补完的那一块：**裁剪之前先问这条限制是否已被别的不变量保证**。0329 的三项各自对应一个已经成立的不变量（memo 的幂等、严格递增的无环性），因此三项都是纯粹的负担。

与 [Round 4](round-04-audit-r1-r12.md) 主线"状态不能太强"是同一族命题——那里是不必维护真实值时维护了真实值，这里是不必维护访问状态时维护了访问状态。

## 主线五：泛化性不等于合适（0221）

0221 的初版走的是逐行转 histogram + 单调栈，复盘后得到二维 DP。两者时间同为 `O(nm)`、空间同为 `O(m)`，笔记的取舍写得很干净：单调栈泛化性更强、能自然处理 histogram 类问题，但实现更复杂，本题 DP 更贴合状态转移特点。

这是 [Round 4](round-04-audit-r1-r12.md) "不镀金"纪律的一个正向样本，且比 [Round 5](round-05-monotonic-stack.md) 主线六又前进了一步：R5 的三处是**事后核算**变体成本，0221 是在两个都能走通的方案之间**主动选了更贴题的那个**，并写出了理由。判据可以固定为：复杂度同阶时，选与问题结构对应关系更直接的方案，泛化能力留给真正需要泛化的场合。

同题另有一条边界提醒：为把空间从 `O(m)` 降到 `O(1)` 而修改输入矩阵，需要权衡代码复杂度与输入语义破坏，不应机械追求。

## 主线六：个人变体的证明成本仍需显式记账（0010 / 0091）

两处一维压缩写法都比标准 DP 紧凑，但都把正确性押在了 invariant 上：

- 0010 把 `*` 视为前一字符的 modifier 而非独立匹配单元，一维压缩后同时依赖 `up`（上一行当前状态）、`pre`（上一行前一真实匹配状态）、`dp[j-1]`（当前行左侧状态）三个量，且 `*` 不更新 `pre`——笔记自己标注"面试时应能明确解释三者分别代表什么"；
- 0091 的写法笔记自陈"比标准 DP 更紧凑，但证明成本更高"，依赖的隐含 invariant 是"之前的 `0` 状态已被过滤，`prevNum == 0` 不会进入后续有效状态"。

两处都做了记账，这一点相对 R5 是保持而非退步。需要注意的是 0097 与 0044 的自适应/greedy 变体**没有做同样的记账**——它们的思路成本确实低（0097 约 5min 得出），但面试表述成本与主流版并不相同。规则应统一为：**变体是否采用取决于思路成本，是否需要记账取决于表述成本，两者不可互相替代。**

## 主线七：wildcard 破坏了 KMP 的前提（0044，独立点）

0044 一度考虑用 KMP 加速固定块匹配，结论是不能直接套用：把 `?` 定义成"与任意字符相等"之后，这种兼容关系**不是等价关系**——它不传递，因此不提供普通字符 equality 所保证的 prefix / suffix 等价性质，failure function 的回退可能失效。最终选择逐位置暴力匹配，最坏 `O(nm)`，与 DP 同阶但空间降到 `O(1)`。

这一条的价值超出本题：**字符串算法的加速结构（KMP / Z / Rolling Hash）几乎都建立在"相等是等价关系"之上，一旦引入 wildcard、近似匹配、带权比较，先验证等价性是否还成立，再决定能否套模板。** 该结论应在 R14（String 算法轮）启动时复查。

## 规则清单

1. 先问状态之间是否存在支配关系：能删被支配者 ⇒ 状态维度可降；删到只剩一个 ⇒ 退化成 greedy。
2. 分支是 DP 的成本来源。唯一合法后继时直接推进，只在真正分叉处展开 DP；"整行唯一可达态"构成 cut，可安全退回单路径。
3. 用题目约束在状态生成前剪掉必死分支，而不是生成后判非法。
4. 状态空间的形状先于转移式：状态是否稀疏、维度是否够（0403 必须带 jump 长度）、能否用映射代替铺满的表。
5. 二维结构问题先定"以某位置为结尾/右下角"的状态，不要从"如何构造目标结构"入手。
6. 加剪枝/加状态之前，先问这条限制是否已被别的不变量保证（memo 的幂等、严格递增的无环性）。
7. 复杂度同阶时选与问题结构对应更直接的方案；泛化性不是选择理由。
8. 变体是否采用看思路成本，是否需要记账看表述成本。
9. 引入 wildcard / 近似匹配后，先验证"相等"是否仍是等价关系，再决定能否套 KMP 类模板。
