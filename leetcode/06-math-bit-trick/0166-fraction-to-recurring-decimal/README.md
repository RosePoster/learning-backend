# 166. Fraction to Recurring Decimal

## 我的思考

读完题后很快想到：

- 整数部分与小数部分分开处理；
- 小数部分本质是模拟长除法；
- 若某个被除数（余数）再次出现，之后的小数一定开始循环，因此用 HashMap 记录第一次出现的位置即可确定循环节。

由于上一题（29）限制不能使用 `/`、`%`，思维惯性导致下意识开始手写十进制长除法，没有意识到本题可以直接使用 `/`、`%` 获得整数部分和余数。

## 卡点

耗时主要集中在实现细节。

思路几分钟内完成，真正耗时的是手写长除法过程以及各种边界处理。

## 关键点

循环小数判定：

将每一次长除法产生的余数作为状态。

若同一个余数再次出现，则之后的小数生成过程完全重复，因此循环节开始于该余数第一次出现的位置。

## 主流解对照

主流实现直接使用整数除法：

- `/` 得到当前位商；
- `%` 得到新的余数；

只对小数部分模拟长除法，不重新实现整数除法过程。

## 复杂度

时间复杂度：`O(k)`，其中 `k` 为生成的小数位数（直到结束或进入循环）。

空间复杂度：`O(k)`。
