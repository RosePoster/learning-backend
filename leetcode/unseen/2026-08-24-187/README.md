# Minimum Adjacent Swaps

## 我的思考

n < 10^5，因此不能实际模拟每一次相邻交换，否则最坏可能达到 O(n²)。

注意到题目只要求最小交换次数，并不要求真的完成交换。一个元素需要贡献多少次交换，只取决于它当前位置和它在已经处理部分中应该插入的位置，因此可以直接计算移动距离。

将数组按值分成三部分：

- P1：num < a
- P2：a <= num <= b
- P3：num > b

最开始考虑维护 P1 起点以及 P2、P3 相对于它的偏移，但实际上不需要维护各段起点，只需要维护两个结束位置：

- p1end：当前 P1 的最后一个位置
- p2end：当前 P2 的最后一个位置

遍历到下标 i 时，已经处理的前缀可以虚拟看作：

[0, p1end] [p1end + 1, p2end] [p2end + 1, i - 1]

当前 nums[i] 根据所属部分插入对应位置：

- 属于 P1：应插入 p1end + 1，需要移动 i - p1end - 1 次；插入后 P1、P2 的结束位置都右移。
- 属于 P2：应插入 p2end + 1，需要移动 i - p2end - 1 次；插入后 P2 的结束位置右移。
- 属于 P3：本身位于最后一部分，不需要移动。

整个过程只维护虚拟分区，不实际修改数组。

## 关键点

只统计 adjacent swap 的次数时，不需要真正执行交换。

把已经扫描过的前缀始终视为稳定分成 P1、P2、P3 三段，当前元素移动到对应段末尾的距离，就是它新增的最小交换次数。
