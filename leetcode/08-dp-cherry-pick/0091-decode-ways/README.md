## 我的思考

使用滚动 DP，但没有直接按照标准的「当前位置由单字符解码和双字符解码转移」来写，而是从 `0` 的特殊性质出发。

观察：

- `0` 无法单独解码，只能作为 `10` 或 `20` 的第二个字符。
- 因此如果提前知道下一位是 `0`，当前字符若被单独使用会导致非法状态。

基于这个特点，在遍历过程中维护：

- `preCount`：前两位状态数量
- `currCount`：当前状态数量

同时维护前一个数字 `prevNum`，判断当前两位是否可以组成合法编码。

核心处理：

- 当前字符为 `0`：
  - 如果前一位不是 `1/2`，非法。
  - 如果下一位还是 `0`，非法。
- 当前字符非 `0`：
  - 默认继承单字符解码数量。
  - 如果当前字符和前一位组成 `10~26`，并且下一位不是 `0`，则增加双字符解码方案。

这种写法本质上是对标准 DP 的优化：
通过提前判断 `0` 的约束，剪掉必死路径。

## 卡点

0 的处理容易出错。

关键在于理解：
- `0` 本身不是一个正常数字状态；
- 遇到 `0` 时，不是在当前状态增加/减少方案，而是在之前已经决定了哪些路径可以合法进入这个 `0`。

因此代码中提前观察下一位：boolean nextNumIsZero = i + 1 < n && s.charAt(i + 1) == '0';

用于避免提前消耗应该留给 `0` 的字符。

## 关键点

- `0` 没有独立解码能力，只能作为 `10` 或 `20` 的后半部分。
- 状态可以压缩为两个变量：
  - 当前方案数
  - 前一个状态方案数
- 通过提前观察下一位，可以剪掉会被后续 `0` 淘汰的路径。

## 主流解对照

标准解法使用滚动 DP：

定义：dp[i] = 前 i 个字符的解码数量

转移：

- 当前字符不为 `0`：
  - 可以单独解码：
    dp[i] += dp[i-1]

- 当前两位属于 `10~26`：
  - 可以组合解码：
    dp[i] += dp[i-2]

空间优化后：
O(n) 时间
O(1) 空间

本题代码等价于该 DP，但利用了 `0` 的约束进行了提前剪枝。

## 复杂度

时间复杂度：O(n)

空间复杂度：O(1)

## 注意

- 本实现依赖一个隐含 invariant：
  当前处理到的位置时，之前的 `0` 状态已经被过滤，因此：prevNum == 0
  的情况不会进入后续有效状态。

- 该写法比标准 DP 更紧凑，但证明成本更高。
