# 97. Interleaving String

耗时：1155min

## 我的思考

最初考虑使用三个指针分别指向 `s1`、`s2`、`s3`。

如果 `s3` 当前字符只与 `s1` 或 `s2` 的其中一边相等，那么当前选择是唯一的，可以直接推进对应指针；真正的问题只出现在：

` s1[i] == s2[j] == s3[i + j] `

此时无法直接判断应该消费 `s1` 还是 `s2`，存在分支。

标准 DP 可以直接解决这个问题，但它会无条件计算整个 `n × m` 状态空间。例如：

`s1 = "abcd", s2 = "eeee", s3 = "abcdeeee"`

整个匹配过程实际上不存在任何分支，只需要 `O(n + m)` 扫描即可，没有必要计算所有 DP 状态。

因此考虑将两种过程结合：

- 当前只有唯一合法选择时，直接进行 forced transition。
- 当 `s1` 和 `s2` 都能匹配当前 `s3` 字符时，进入 DP。
- DP 完整计算一行后，统计该行 reachable 状态数量。
- 如果整行只剩一个 `true`，说明此前所有可能路径已经汇合到唯一状态，可以退出 DP，重新进行 forced transition。
- 如果一行没有任何 `true`，直接返回 `false`。
- 如果一直没有收敛，则最坏情况下退化为完整 DP。

## 卡点

最初比较难确定 DP 应该在什么条件下重新切换回单路径推进。

最终利用完整 DP 行作为 cut：如果某一整行只有一个 reachable state，那么任何能够继续到达终点的合法路径都必须经过这个唯一状态，因此之前的分支历史已经没有意义，可以安全重新进入 forced phase。

另一个实现问题是多次进入 DP 是否需要重新清空 `dp`。通过维护“DP 只在完整一行唯一 `true` 时退出”以及 `s2Idx` 单调不减，可以证明右侧旧状态不会污染后续计算，因此无需 `Arrays.fill`。

## 关键点

DP 状态含义为：

`dp[i][j]` 表示 `s1` 的前 `i` 个字符和 `s2` 的前 `j` 个字符能否组成 `s3` 的前 `i + j` 个字符。

rolling array 中：

- `dp[j + 1]` 更新前表示上一行状态，即从 `s1` 转移。
- `dp[j]` 已经是当前行状态，即从 `s2` 转移。

只有一个合法 successor 时不需要 DP，可以直接推进。

进入 DP 后必须完整计算一整行以后才能判断是否收敛，不能在一行计算到一半时因为暂时只有一个 `true` 就退出。

若完整一行的 `trueSize == 1`，则该行构成一个只有唯一 reachable state 的 cut，可以重新退化为单路径推进。

## 主流解对照

主流解法直接使用二维 DP，并压缩成一维滚动数组：

`dp[j] = (dp[j] && matchS1) || (dp[j - 1] && matchS2)`

无论输入是否存在实际分支，都需要计算整个 `n × m` 状态空间，时间复杂度为 `O(nm)`。

本解法是在标准 DP 基础上的 adaptive optimization：

- 无歧义区间只进行 forced transition。
- 只有出现实际分支时才展开 DP。
- 多条路径重新汇合后立即退出 DP。

因此简单输入可以避免大量无意义状态计算，同时保留标准 DP 的最坏复杂度上界。

## 复杂度

最坏时间复杂度：`O(nm)`

最好时间复杂度：`O(n + m)`，即整个过程中不存在需要展开的分支。

空间复杂度：`O(m)`

## 注意

这里严格来说不是 greedy，因为唯一选择阶段没有进行任何贪心决策，只是在执行 forced transition；一旦存在两个合法选择就立即交给 DP。

每次从 DP 返回 forced phase 时必须保证当前完整行恰好只有一个 reachable state，这是复用旧 `dp` 且不执行 `Arrays.fill` 的核心 invariant。

`s1Idx` 和 `s2Idx` 在整个算法中都只会单调增加，因此已经越过的 DP 区域不会再次参与后续计算。
