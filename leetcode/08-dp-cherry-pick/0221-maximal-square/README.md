# 221. Maximal Square

耗时：未记录（计时器数据作废）

## 我的思考
首先尝试直接在二维矩阵中寻找最大的正方形，但发现状态较难维护，需要判断当前区域是否闭合，以及向左、向下扩展是否合法。

随后考虑逐行处理：
- 当前行中连续的 `1` 可以作为正方形候选的宽度；
- 但只看当前行无法判断向下是否存在足够高度。

进一步想到：
- 如果记录每一列向上的连续 `1` 数量，就能同时获得高度信息；
- 每处理一行，就可以把矩阵转换成一个 histogram 问题；
- 对当前 histogram 使用单调栈，计算每个位置作为最低高度时能形成的最大正方形边长。

实现过程中使用：
- `currValue[m]` 保存每列截至当前行的连续高度；
- 单调栈维护递增高度序列；
- 弹出柱子时计算可形成正方形的最大边长：
  `min(width, height)`。

之后复盘得到 DP 解法：
将状态定义为以当前位置作为右下角的最大正方形边长。

## 卡点
一开始认为二维状态复杂，难以直接判断一个正方形区域是否合法。

没有第一时间想到 DP，因为思考方向偏向“构造正方形”，而不是“以某个位置作为结尾的最大状态”。

## 关键点
DP 状态：

`dp[i][j]` 表示以当前位置 `(i,j)` 为右下角的最大正方形边长。

如果当前位置为 `1`：

`dp[i][j] = min(左，上，左上) + 1`

原因：
- 左边限制宽度；
- 上方限制高度；
- 左上限制内部已有正方形大小。

最终：
- 时间复杂度 `O(nm)`
- 空间复杂度 `O(m)`

## 主流解对照
主流解法为二维 DP，而非 histogram + 单调栈。

两者复杂度相同：

- 时间：`O(nm)`
- 空间：`O(m)`

单调栈方案：
- 优点：能够自然处理 histogram 类问题，泛化性较强；
- 缺点：实现更复杂，本题中不如 DP 直接。

DP 更符合本题的状态转移特点。

## 复杂度
DP：

时间复杂度：`O(nm)`

空间复杂度：`O(m)`

单调栈：

时间复杂度：`O(nm)`

空间复杂度：`O(m)`

## 注意
- 面对二维矩阵问题，不要只考虑“如何构造目标结构”，可以尝试固定一个位置作为状态终点。
- “以某个位置作为右下角/结尾”的状态定义经常能降低二维问题复杂度。
- 单调栈中相同高度是否立即弹出取决于实现方式，本题使用 `<` 保留相同高度也正确。
- 为了从 `O(m)` 降到 `O(1)` 而修改输入矩阵，需要权衡代码复杂度和输入语义破坏，不应机械追求。
