# 329. Longest Increasing Path in a Matrix

## 我的思考
这题思路比较直白，关键在于利用矩阵中严格递增的关系。

严格递增意味着路径中不会出现环，因此可以直接使用 DFS 搜索，并通过记忆化保存每个位置作为起点时的最长路径长度。

初版实现时，考虑了几个额外状态：
- `-2` 表示该点不是路径起点，不需要从这里开始搜索；
- `-1` 表示正在访问，用于防止 DFS 过程中形成环；
- `0` 表示未计算；
- 正数表示该点作为起点的最长递增路径长度。

为了减少无效搜索，额外设计了 `check`：
- 如果周围存在更小元素，则该点一定不是全局起点；
- 如果周围存在更大元素，则将更大元素标记为非起点。

后续发现这些优化实际上没有必要，因为：
- 是否为起点并不影响记忆化 DFS 的正确性；
- 每个节点最多只会被完整计算一次；
- 严格递增关系天然保证不存在环。

最终简化为直接 DFS + Memo。

## 卡点
无

## 关键点
矩阵中的严格递增路径构成一个隐式 DAG（Directed Acyclic Graph）。

由于每一步只能移动到更大的数字：
- 不可能回到已经访问过的位置；
- 每个节点的最长路径结果固定。

因此可以定义：

`dp[i][j] = 从(i,j)出发能够形成的最长递增路径长度`

状态转移：

`dp[i][j] = 1 + max(dp[next])`

其中 `next` 是所有值大于当前位置的相邻节点。

## 主流解对照
初版额外加入了起点筛选和访问状态标记。

这些优化没有必要：
- 任意节点都可以作为 DFS 起点；
- memo 已经保证重复状态不会重复计算；
- 严格递增条件已经排除了 DFS 环。

主流写法通常直接使用 DFS + memo，通过返回值表达状态。

## 复杂度
时间复杂度：O(mn)

每个格子只会计算一次，每次检查四个方向。

空间复杂度：O(mn)

memo 数组占用 O(mn)，递归栈最坏 O(mn)。

## 注意
这题容易被误认为需要处理 DFS 环，但严格递增条件已经隐含保证无环。

设计状态时优先考虑：
- 当前状态是否能唯一确定答案；
- 是否存在重复计算。

如果 memo 已经解决重复计算，不要过早加入额外剪枝状态。

初版的 `check` 属于尝试降低搜索范围，但没有降低渐进复杂度，反而增加状态复杂度。
