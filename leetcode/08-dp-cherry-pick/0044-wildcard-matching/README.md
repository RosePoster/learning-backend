# 44. Wildcard Matching

耗时：<1min

## 我的思考

这题和 10 题的结构很接近。`*` 不绑定具体字符，可以理解成 10 题中 `*` 固定修饰 `.` 的版本，因此很容易直接得到 DP解。

继续考虑能否利用 `*` 的性质压缩状态。

可以把 pattern 看成“弹簧 + 木棍”交替组成：

- `*` 是弹簧，可以匹配任意长度字符串。
- 两个 `*` 之间的普通字符 / `?` 是木棍，长度固定，必须整体匹配。

pattern 首尾没有 `*` 覆盖的部分没有伸缩空间，因此可以先从两端直接匹配掉。处理之后，中间结构可以看成：

`* B1 * B2 * ... * Bk *`

其中 `Bi` 是不含 `*` 的固定长度块。

一开始担心：一个块可能在字符串中存在多个合法匹配位置，不同选择会影响后续块，因此似乎需要把所有位置全部尝试。

之后发现，可以始终选择当前块的最早合法匹配位置。

假设存在某个完整可行解，其中当前块位于位置 `x`，而我找到的最早位置为 `g`，必然有 `g <= x`。选择 `g` 后留给后续块的字符串只会更多，不会更少，因此原来从 `x` 后能够完成的匹配，从 `g` 后仍然有机会完成。

所以更晚的匹配位置全部被最早位置支配，不需要保存这些分支。

于是按顺序寻找每个块最早的合法 occurrence 即可。

寻找块时原本考虑 KMP，但 `?` 的 wildcard 语义使标准 KMP 的 prefix / failure function 不能直接按照普通字符相等关系构造。没有必要为此实现特殊版本，因此直接逐位置暴力尝试每个块。

## 卡点

最开始认为同一个固定块的不同匹配位置都可能影响最终答案，因此需要保留多个状态。

后来意识到最早匹配位置具有 dominance：它给后续 pattern 留下的空间最大，因此更晚的位置没有保留价值。

另外一度考虑使用 KMP 加速块匹配，但标准 KMP 不能直接把 `?` 当作普通的“相等”关系处理。

## 关键点

将 pattern 按 `*` 切成若干固定长度块。

对于中间每个块，只需要寻找当前剩余字符串中的最早合法匹配位置。若存在完整解，那么把任意一个块向左移动到更早的合法位置，都不会破坏后续块的相对顺序和可用空间。

因此可以用 greedy 消除 DP 中对不同匹配位置的状态枚举。

首尾没有 `*` 保护的部分必须严格贴着字符串首尾匹配，可以提前处理。

## 主流解对照

更常见的实现是双指针 greedy：记录最近一次遇到的 `*` 以及该 `*` 当前吞到的字符串位置；发生失配时，让最近的 `*` 多吞一个字符，再从 `*` 后继续匹配。

我的实现采用的是按 `*` 分块后，为每个固定块寻找最早 occurrence。两者利用的是一致的 greedy 性质：尽量让前面的 `*` 少吞字符，把更多空间留给后续 pattern。

相比之下，DP 会保留所有 `(sPrefix, pPrefix)` 状态，而 greedy 利用 dominance 直接删除大量没有必要的分支。

## 复杂度

块匹配采用逐位置暴力尝试。

时间复杂度：最坏 `O(nm)`。

空间复杂度：`O(1)`。

虽然 worst-case time 与 DP 同阶，但实际不再枚举完整二维状态空间，并把额外空间从 `O(m)` 降到了 `O(1)`。

## 注意

标准 KMP 不能简单地通过定义“`?` 与任意字符相等”后直接套用。wildcard 的兼容关系不具备普通字符 equality 所提供的 prefix / suffix 等价性质，因此 failure function 的回退可能失效。
