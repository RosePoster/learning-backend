# 236. Lowest Common Ancestor of a Binary Tree

## 我的思考
本次复刷耗时 8min。使用 `boolean dfs` 判断当前子树是否包含 `p/q`，用全局 `ans` 单独记录已经确认的 LCA。

这种写法语义比较分离：`dfs` 只负责返回“是否包含目标节点”，`ans` 只在确认同时包含 `p` 和 `q` 时赋值。因此如果 `p/q` 并非都在树中，最终会返回 `null`。

## 卡点
没有想清楚主流返回节点版中，“找到了一个目标节点”和“找到了 LCA”这两种语义可以共用同一个返回值。

## 关键点
主流解法在 `root == p || root == q` 时直接返回 `root`。

这个返回值可能表示：
1. 找到了一个目标节点；
2. 找到了 LCA。

但这不影响原题正确性，因为题目默认 `p` 和 `q` 都在树中。父层通过左右子树返回值判断：若左右都非空，则当前节点是 LCA；否则继续向上传递非空节点。

## 主流解对照
主流返回节点版代码更简洁，但返回值同时承载两种语义，无法区分“已找到 LCA”还是“只找到一个目标节点”。

因此即使某一侧已经返回非空，也仍要遍历另一侧确认，常数时间复杂度略高。

当前 `boolean + ans` 写法更显式，也能在找到答案后剪枝；但代码状态更多。

## 复杂度
时间复杂度：O(n)  
空间复杂度：O(h)

## 注意
原题默认 `p/q` 都存在，主流解法没问题。若泛化到“不保证节点存在”的场景，主流解法可能静默返回单个存在节点，需要额外校验。
