# 2104. Sum of Subarray Ranges

## 我的思考
一开始想到单调栈，但思路一直被局限在具体的每一个子数组范围内，也就是试图同时处理某个子数组的最大值和最小值。

这样会很难做。即使用单调栈找出左右边界，也只能分别找出最大值范围或最小值范围，而最大值范围和最小值范围不太可能完美重合。中间差异部分很难处理，比如某块数组最大值来自左边，最小值来自右边，这种情况不好统一表达。

期间也想到过其他方法。例如状态转移：假定前 `k` 个元素已经处理，第 `k + 1` 个元素加入后答案如何变化。但这个方向无法很好表达状态。

也尝试过逐项计算差值。例如 `[4, -2, -3, 4, 1]` 的相邻差值为 `[6, 1, -7, 3]`，想用“`a` 到 `c` 的距离等于 `a` 到 `b` 加 `b` 到 `c`”的方式处理，但仍然很复杂，需要判断中间元素与两端元素的大小关系。

最后列出式子：

`subRange = max - min`

然后想到最大值和最小值不必绑定在一起，因为求的是所有子数组的范围之和：

`sum(subRanges) = sum(max_ij - min_ij)`

所以可以拆成所有子数组最大值贡献之和减去所有子数组最小值贡献之和。

## 卡点
一开始虽然想到单调栈，但一直被限制在“每个具体子数组的最大值和最小值如何同时处理”这个角度里，导致问题很难推进。

最大值范围和最小值范围无法完美重合时，中间差异部分难以处理，这是前期主要卡住的地方。

实现时又卡在单调栈比较符号的选择上：到底应该全取 `<`，全取 `<=`，还是一边取 `<`、另一边取 `<=`。写到这里时已经比较累，没有精力继续具体分析，而是把几种写法都尝试了一遍，最后发现只有一边严格、一边非严格能够 AC。

这个问题当时没有真正解决，而是靠尝试凑过去了。

## 关键点
这题的关键转折是：不要把同一个子数组里的最大值和最小值强行绑定在一起处理。

因为：

`range = max - min`

所以所有子数组的范围和可以拆成：

`所有子数组最大值之和 - 所有子数组最小值之和`

这样最大值贡献和最小值贡献可以分别计算。

重复元素的比较符号不能靠试。对于同一类贡献，必须一边严格、一边非严格，用来规定相等元素的归属，避免重复计算或漏算。

本题代码里的归属方式是：

最大值：

- 左边界使用 `nums[i] > nums[stack.peek()]`
- 右边界使用 `nums[i] >= nums[stack.peek()]`

等价于：

- `left = previous greater or equal`
- `right = next strictly greater`

最小值：

- 左边界使用 `nums[i] < nums[stack.peek()]`
- 右边界使用 `nums[i] <= nums[stack.peek()]`

等价于：

- `left = previous less or equal`
- `right = next strictly less`

## 复杂度
时间复杂度：`O(n)`

空间复杂度：`O(n)`

## 注意
以后遇到所有子数组的 `max - min`、`max + min`、最大值总和、最小值总和这类问题时，优先考虑能否拆成单个元素作为最大值或最小值的贡献次数，而不是绑定在具体子数组里一起处理。

单调栈处理重复元素时，不要再靠尝试比较符号 AC。要明确相等元素归属：一边严格，一边非严格。
