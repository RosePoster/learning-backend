# 456. 132 Pattern

## 我的思考
一开始将问题理解为：找一个下标 `idx` 及其对应值 `curr`，使得 `idx` 左右两边都有小于 `curr` 的值，并且左边的值小于右边的值。

但实现时发现这个方向很难处理。左边可以贪心找最小值，右边则需要找小于 `curr` 的最大值，这一点无法干净实现。

随后转化为：找一个下标 `idx` 及其对应的 `curr`，在左边找第一个大于 `curr` 的值 `greater`，再找最远一个小于 `curr` 的值 `lower`，判断二者下标关系是否满足要求。

这个转化后来发现有问题：试图用单调栈简单改造来找“最远一个小于当前值”的下标并不可行。比如 `[3,5,0,2,4]` 中，`4` 对应的结果会找到 `0`，而不是最远的 `3`。

意识到单调栈无法通过简单改造实现找最远后，重新转化为：枚举当前值 `curr` 作为 132 模式中的 `2`，在它左边找一个大于它的 `greater` 作为 `3`，再判断 `greater` 左边是否存在一个最小值 `lowest` 小于 `curr`。如果存在，则找到答案。

## 卡点
主要卡在试图用单调栈找“最远一个小于当前值”的下标。

单调栈擅长找最近的更大/更小元素，但不能通过简单改造稳定得到最远的更大/更小元素。这一点是本题耗时中最主要的卡点。

另一个问题是，最开始试图把 `1、3、2` 三个角色的关系直接绑定在同一个局部结构里处理，导致需要同时考虑左边最小、右边小于当前值的最大值、以及下标顺序，关系变得很难维护。

## 关键点
单调栈只能稳定解决“最近更大/最近更小”这类边界问题，不要默认它能通过简单改造解决“最远更大/最远更小”。

如果需要维护左侧最小值下标，不需要使用单调栈，直接前缀最小下标即可：

`minIdx[i] = nums[i] < nums[minIdx[i - 1]] ? i : minIdx[i - 1];`

这题更干净的转化是：枚举当前值作为 `2`，在左侧找一个比它大的 `3`，再判断这个 `3` 左侧是否存在一个比当前值更小的 `1`。

## 复杂度
时间复杂度：`O(n)`

空间复杂度：`O(n)`

## 注意
这题的主要收获不是某个模板，而是思路迭代过程：

从直接绑定左右关系，到尝试找最远小于当前值，再到意识到单调栈不适合找最远，最后改为围绕当前值作为 `2` 重新组织条件。

如果某个边界需要“最远”，普通单调栈可能不适用。
