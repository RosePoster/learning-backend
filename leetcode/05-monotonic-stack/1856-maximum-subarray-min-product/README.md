# 1856. Maximum Subarray Min-Product

## 我的思考
一开始考虑滑动窗口，但发现窗口内最小值和区间和都会变化，无法稳定控制。

随后转向暴力思路：枚举窗口并计算最小值与区间和。

之后很快想到可以使用 `left`、`right` 数组配合单调栈快速计算每个位置对应的结果。

## 卡点
主要卡在实现阶段，而不是思路阶段。

一开始写的是出栈时确定边界的写法，需要遍历结束后额外后处理栈内元素。后来想消除后处理，改成当前这种写法，在这个切换过程中卡了不少时间。

调试和优化混在了一起，导致代码还没稳定时，就同时调整了单调栈写法、边界处理和后处理方式。

对 `int` 和 `long` 的范围把握不够精细。虽然知道二者分别是 32 位和 64 位，但到边界处容易混乱，不确定哪些地方会溢出，哪些地方必须转成 `long`。

对 `(int)`、`%`、加减乘除等运算的优先级不够熟，导致取模和强转位置反复修改。

`10^9 + 7` 的写法不够熟，后面数 0 时也出现了卡顿。

## 关键点
实现时不要把 debug 和优化混在一起。应该先用一种熟悉的写法写出稳定版本，再考虑是否消除后处理或调整结构。

涉及取模和强转时，固定写法：

`(int)(ans % MOD)`

不要写成：

`(int) ans % MOD`

因为后者会先强转，再取模。

`MOD` 固定写成：

`1_000_000_007`

避免手写 `1000000007` 时数错 0。

涉及前缀和、乘法结果时，优先使用 `long`，不要等到边界处再临时判断。

## 复杂度
时间复杂度：`O(n)`

空间复杂度：`O(n)`

## 注意
这题复盘重点不是单调栈抽象，而是 Java 数值表达式和实现流程稳定性。

以后遇到类似题，先固定一种单调栈写法完成 AC，不要在调试阶段同时改写法、改边界、改比较符号和改后处理。
