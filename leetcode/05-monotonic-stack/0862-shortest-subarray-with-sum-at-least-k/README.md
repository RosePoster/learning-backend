# 862. Shortest Subarray with Sum at Least K

## 我的思考
读题后首先想到维护非负前缀和（即截断负数），因为非负前缀和代表当前能够得到的最大子数组和；如果非负前缀和都达不到 `k`，则一定不存在答案。

随后发现问题变成：满足条件的前缀和可能很多，需要找到最短子数组。

于是转化为：对于当前前缀和 `currSum`，需要找到所有满足 `preSum <= currSum - k` 的历史前缀中，下标最大的那个。

最开始考虑使用红黑树，但普通红黑树虽然容易找到满足阈值的 `key`，却无法直接维护对应最大的 `value`。

继续推导后，发现可以维护支配关系：

如果存在一个前缀 `(preSum1, idx1)` 和 `(preSum2, idx2)`，满足：

- `preSum1 <= preSum2`
- `idx1 >= idx2`

那么 `(preSum2, idx2)` 永远不会比 `(preSum1, idx1)` 更优，可以直接删除。

这样维护后，TreeMap 中 `preSum` 递增时，`idx` 也必然递增，因此查询 `floorKey(currSum - k)` 时，对应的就是满足条件的最大下标。

## 卡点
一开始想到红黑树后，卡在如何同时维护：

- 满足 `preSum <= currSum - k`
- 下标尽可能大

普通红黑树无法直接完成这一点。

随后花了一段时间推导支配关系，才发现可以通过删除被支配状态，使 `preSum` 与 `idx` 保持单调对应。

## 关键点
本题真正维护的是前缀状态之间的支配关系。

若存在：

- 更小（或相等）的前缀和
- 更大的下标

则另一状态永远不会成为最优解，可以直接删除。

这样维护后，TreeMap 中：

- `preSum` 单调递增
- `idx` 也随之单调递增

因此查询 `floorKey(currSum - k)` 时，就能直接得到满足条件的最大下标。

## 主流解对照
主流解法使用前缀和 + 单调队列，将时间复杂度进一步优化到 `O(n)`。

本次采用的是维护支配关系的 `TreeMap` 解法，时间复杂度为 `O(n log n)`。

## 复杂度
时间复杂度：`O(n log n)`

空间复杂度：`O(n)`

## 注意
实现时前缀和必须使用 `long`，不能使用 `int`，否则前缀和可能溢出导致错误。
