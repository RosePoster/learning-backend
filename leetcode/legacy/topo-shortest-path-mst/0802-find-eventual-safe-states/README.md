# 802. Find Eventual Safe States

## 我的思考
本题完全没卡。

使用 DFS 判断每个节点是否最终安全。`isSafe[curr]` 表示当前节点是否已经确认安全，`visited[curr]` 表示当前节点是否已经被访问过。

一个节点安全，当且仅当它的所有后继节点都安全。因此 DFS 遍历当前节点的所有出边：如果某个后继节点尚未访问，则先递归访问；访问完成后，如果该后继节点不是安全节点，则当前节点也不安全，直接返回。只有所有后继节点都安全时，才将当前节点标记为安全。

没有额外区分“当前 DFS 路径中遇到环”和“已经确认不安全”的节点。因为对当前节点而言，这两种情况严格等价：只要某个后继节点不是安全节点，当前节点就不安全。

如果题目要求区分环中节点、正在访问节点、已确认不安全节点，则需要增加状态数组，或者改成三色标记。但本题只需要判断 safe / unsafe，因此 `visited + isSafe` 足够。

## 卡点
无。

## 关键点
- 一个节点安全，当且仅当它的所有后继节点都安全。
- `visited && !isSafe` 同时覆盖两种情况：
  - 当前 DFS 路径中遇到环；
  - 该节点已经被确认不安全。
- 在本题中，上述两种情况对当前节点的影响相同，因此不需要显式区分。
- 如果某个后继节点不安全，当前节点立即返回，不标记为安全。
- 只有所有后继节点都安全时，当前节点才标记为 `isSafe = true`。

## 复杂度
- 时间：`O(V + E)`
- 空间：`O(V)`

## 注意
- 当前写法是对三色 DFS 的状态压缩版本。
- 这种压缩只适合本题这种只关心 safe / unsafe 的场景；如果需要输出环、区分 visiting / unsafe，不能继续合并状态。
