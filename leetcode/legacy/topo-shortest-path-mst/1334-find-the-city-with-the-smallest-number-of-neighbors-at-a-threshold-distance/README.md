# 1334. Find the City With the Smallest Number of Neighbors at a Threshold Distance

## 我的思考
本题花费约 60min。

一开始没有第一时间命中 Dijkstra，而是试图复用计算结果。最初想过一个递归方法：某个节点访问过，意味着该节点边表里已经记录了该节点在阈值内所有能到达的节点与距离；后续节点如果走到它，就可以递归复用这些结果。但这个思路无法直接实现，因为最短路之间存在互相依赖。

随后切换为 Dijkstra。由于之前没有真正实现过 Dijkstra，先实现普通版本。实现过程中遇到一个基础问题：优先队列不能只比较外部 `dist` 数组，因为 `dist` 更新后，已经在队列中的元素不会自动重排。正确做法是将 `{node, distSnapshot}` 放入优先队列。

普通 Dijkstra 写完后，又继续考虑复用。思路是：`visit(curr)` 之前，编号小于 `curr` 的节点都已经访问过；此时 `limGraph[j] (j < curr)` 不再是原始邻接边，而是节点 `j` 在阈值内可达的所有城市及最短距离。

因此，在 `visit(curr)` 的 Dijkstra 中，如果当前确定的最小距离节点 `j < curr`，就可以直接用 `limGraph[j]` 批量更新当前 `dist`。这些由 `limGraph[j]` 产生的新状态不需要再入优先队列，因为从 `j` 出发能继续到达的最优结果已经包含在 `limGraph[j]` 的最短路闭包里。

最后，在 `visit(curr)` 结束前，将本轮得到的 `dist` 翻译为 `ArrayList<int[]>`，替换 `limGraph[curr]`，使其从原始边升级为阈值内最短路缓存。该版本可以运行通过。

## 卡点
- 一开始没有立即识别为带正权边的最短路问题，先尝试了递归复用，但最短路不是普通 DAG 递归，节点之间会互相依赖。
- 第一次实现 Dijkstra，对优先队列和 `dist` 的关系不熟：队列中元素不会随着外部 `dist` 数组变化而自动重排，必须入队距离快照。
- 普通 Dijkstra 写完后，又尝试跨源复用结果，导致实现复杂度上升。
- 缓存复用版需要非常明确 `limGraph` 的语义变化：对于未处理节点，它是原始邻接边；对于已处理节点，它是阈值内最短路闭包。
- 本题主要问题不是最终算法不可行，而是启动慢，并且在复用优化上投入了较多推导成本。

## 关键点
- 对每个城市跑一次 Dijkstra，可以统计阈值内可达城市数量。
- `dist` 初始化为 `distanceThreshold + 1`，表示暂时未在阈值内可达。
- 松弛时计数是正确的：一旦某个节点第一次被松弛到 `<= distanceThreshold`，就已经确定存在一条阈值内路径，不需要等到最短距离最终出队确认。
- tie-breaking 通过从小到大遍历城市，并在 `currCount <= minCount` 时更新答案，自然保留编号更大的城市。
- 缓存复用版中，若 `j < curr`，则 `limGraph[j]` 已经保存从 `j` 出发的阈值内最短距离，可以用 `dist[curr][j] + dist[j][x]` 批量更新当前 `dist`。
- 缓存复用成立的前提是：`limGraph[j]` 已经完整保存 `j` 的阈值内最短路结果，而不是原始邻接边。

## 主流解对照
主流解通常使用 Floyd-Warshall 求全源最短路，或对每个城市分别跑 Dijkstra，再统计阈值内可达城市数量。Floyd 写法更短，Dijkstra 更适合稀疏图。我的普通版本属于每点 Dijkstra；缓存复用版是在此基础上做跨源最短路结果复用，属于直接建模下的优化变体。

## 复杂度
普通 Dijkstra 版本：
- 时间：`O(n * (E log n))`
- 空间：`O(n + E)`

缓存复用版本：
- 时间：最坏情况下仍可能接近多次 Dijkstra 或更高，取决于缓存闭包大小；在阈值内可达点较多时，批量扫描 `limGraph[j]` 的成本可能上升。
- 空间：`O(n^2)` 最坏情况下，每个 `limGraph[i]` 都可能缓存大量阈值内可达节点。

## 注意
- 第一次写 Dijkstra，且在“递归复用 / 缓存闭包复用”上花了较多时间。
- 普通 Dijkstra 是更稳的限时首选；缓存复用版有结构美感，但证明和实现成本较高。
- 后续复刷重点：
  - 快速识别正权图阈值可达问题可用 Dijkstra / Floyd；
  - Dijkstra 优先队列中存 `{node, distSnapshot}`；
  - 明确松弛时计数的语义；
  - 如果做缓存复用，必须清楚区分 `limGraph` 在处理前后的语义变化。
