# 1368. Minimum Cost to Make at Least One Valid Path in a Grid

## 我的思考
没有见过 0-1 BFS，从题目结构中推出了一个等价思路：

被箭头链接的一片网格可以视为同一个图节点，它们之间的代价为 0。不同片节点之间如果“挨着”，也就是节点之间至少有一个网格相邻，则它们之间有边，边的代价为 1。

因此可以把沿箭头方向的移动视为当前 cost 下的免费扩展。`visit` 从一个格子出发，沿箭头方向一路访问所有当前 cost 下免费可达的格子，并把这些格子加入队列。外层 BFS 每扩展一层，表示额外修改一次方向，cost +1。

第一版 `visit` 使用递归，写起来更简单，但可能有递归栈风险。后续重构为 `while` 循环版本，避免递归栈，同时用 `visited` 记录格子是否已访问，用外层 BFS 层数维护当前 cost。

这版写法和通用 0-1 BFS 思想一致，但更贴合本题结构：本题每个格子只有一个箭头方向，也就是每个点只有一条 0-cost 出边，所以 `visit` 可以直接顺着箭头滑行。

如果存在多条 0-cost 边，`visit` 也可以改成内部 BFS/DFS，把所有 0-cost 可达节点一次性吃完。也就是说，本质仍然是：外层按 `+1 cost` 分层，内层吃掉当前层所有 0-cost closure。

## 卡点
无明显卡点。

## 关键点
- 沿箭头方向移动的代价为 0，可以在当前 cost 层内一次性展开。
- 从当前 0-cost closure 中任意格子向四周走一步，相当于修改一次方向，代价 +1。
- 外层 BFS 的层数就是当前修改次数。
- 终点第一次被 `visited` 时，就是最小代价。
- `visit` 中 closure 上的每个格子都需要入队，因为这些格子都可能作为下一层改方向的出发点。

## 复杂度
- 时间：`O(nm)`
- 空间：`O(nm)`

## 注意
- 第一版递归 `visit` 更直观，重构版循环 `visit` 更优。
- 通用 0-1 BFS 是：0 代价边放队头，1 代价边放队尾。本题因为每个格子只有一条 0-cost 出边，所以用 `visit` 顺箭头滑行更贴题，也容易早停。
- 若以后遇到多条 0-cost 边的变体，可以把 `visit` 从 while 滑行改成内部 BFS/DFS，吃完当前 cost 下的 0-cost closure。
