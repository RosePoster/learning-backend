# 1249. Minimum Remove to Make Valid Parentheses

## 我的思考
本题一开始没有从栈的角度切入，而是直接从括号合法性的修复过程出发。

### 解法1：正向跳过非法右括号，反向删除多余左括号

第一种解法的思路是两阶段处理：

1. 从左往右扫描，删除无法匹配的右括号 `)`。
   - 用 `leftCount` 记录当前尚未匹配的左括号数量。
   - 遇到 `(` 时，`leftCount++`。
   - 遇到 `)` 时，如果 `leftCount == 0`，说明该右括号无法匹配，需要跳过；否则 `leftCount--`。

2. 第一阶段结束后，剩余的 `leftCount` 表示多余的左括号数量。
   - 从右往左扫描剩余字符串。
   - 遇到 `(` 且仍有多余左括号需要删除时，跳过该左括号。
   - 其余字符正常保留。

该解法本质上是：
- 正向处理非法右括号；
- 反向处理多余左括号。

但第一版实现时使用 `left/right` 指针维护片段边界，并分段拼接字符串，虽然逻辑可行，但代码语义比较压缩，阅读门槛偏高。

### 解法2：显式统计删除额度

后来尝试构造一种更符合直接建模风格的解法：

1. 先统计：
   - `leftCount`：左括号总数；
   - `rightCount`：右括号总数；
   - `misMatch`：从左往右扫描时，无法被任何左括号匹配的右括号数量。

2. `misMatch` 个右括号属于位置失配，必须删除。
   - 删除这些右括号后，剩余可参与匹配的右括号数量为 `rightCount - misMatch`。

3. 再根据剩余左右括号数量，确定最终可以保留多少个左括号，以及还需要额外删除多少个右括号。
   - 如果左括号多于剩余右括号，则只保留与右括号数量相同的左括号。
   - 如果右括号仍然多于左括号，则继续增加需要删除的右括号数量。

4. 最后从左往右构造答案：
   - 需要删除的右括号优先删除靠左的右括号；
   - 需要删除的左括号通过限制可保留左括号数量实现，相当于优先删除靠右的左括号。

该解法不算输出字符串时，可以做到 `O(1)` 额外空间。  
它的思想分层更显式：先处理位置失配，再处理数量失配，最后根据删除额度构造答案。

## 卡点
- 认为本题不必要使用栈，而是可以直接建模，于是没有使用栈来匹配括号。
- 解法1 的整体方向是对的，但实现时使用 `left/right` 指针分段拼接，导致代码可读性不够好。
- 后续尝试构造更统一的动态删除模型时，最开始的想法在 `"())(("` 这类 case 上会失败：从左往右贪心删除多余左括号，会删掉本可以和后续右括号匹配的左括号。
- 修正后认识到：多余左括号应优先删除靠右的左括号；多余右括号应优先删除靠左的右括号。
- 解法2 可以成立，变量语义需要非常清楚，否则容易把“位置失配”和“数量失配”混在一起。

## 关键点
- 括号合法性可以拆成两个条件：
  1. 任意前缀中，右括号不能多于左括号；
  2. 最终左括号不能多余。
- 解法1 对应这两个条件：
  - 正向扫描删除非法右括号；
  - 反向扫描删除多余左括号。
- 解法2 显式拆分为：
  - 位置失配：无法匹配的右括号必须删除；
  - 数量失配：根据剩余左右括号数量决定额外删除哪一侧。
- 对于左括号多余的情况，应优先删除靠右的左括号，因为靠左的左括号更可能匹配后续右括号。
- 对于右括号多余的情况，应优先删除靠左的右括号，因为靠左且无法被前缀左括号匹配的右括号更容易造成前缀非法。
- 本题可以用栈做，也可以用两遍扫描做；两遍扫描可以看作对栈匹配语义的空间优化实现。
- 解法2 更符合直接建模风格，但证明和变量语义要求更高；面试中解法1 的两遍扫描版本更容易解释。

## 复杂度
### 解法1
- 时间：`O(n)`
- 空间：`O(n)`，用于构造中间字符串和答案。

### 解法2
- 时间：`O(n)`
- 空间：`O(1)`，不计输出字符串。
