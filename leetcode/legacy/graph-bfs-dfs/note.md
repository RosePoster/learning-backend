## 〇、跨题 Insight（README 没明说但代码暴露出来的）

### 1. DFS→BFS 反复改方向，根因是 DP 思维侵入图问题
- `127` 用 DFS 是“判存在”、`542` 用 DFS+memo 是“当前点 = 1 + min(四邻)”——表面是两种错误，本质都是**先想“答案怎么由邻居算出来”（局部递推 / DP 思维）**，而不是**“搜索空间长什么样”（全局扩展思维）**。
- 这是模型选择层的卡点，不是 BFS/DFS 实现层。识别钩子：题目问“最短”，脑里却在写递推式 → 立刻警觉，这不是 DP 是 BFS。

### 2. visited 的类型 = 状态空间的维度
本轮 15 份 Solution 里 visited 出现了 3 种写法，对应 3 种状态空间：
| visited 类型 | 状态空间 | 代表题 |
|---|---|---|
| boolean / 原地 sentinel | 仅位置 | 大多数网格题 |
| `int[][]` 存“最优代价” | 位置 + 连续代价维度 | `1293`（剩余障碍数） |
| 两个 boolean 数组取交 | 位置 + “被谁可达”集合维度 | `0417` |

**“visited 该记什么”等价于问“状态空间是什么”。** 当本能想往 visited 塞标量以外的东西时，真正在做的是给状态加一维——这条比 `1293` 笔记里写的“visited 可以不是 boolean”更本质。

### 3. 难度的真分水岭：是不是隐式图
- 网格题 10 道（`0130/0542/0695/0733/0934/0994/1091/1162/1293/1926`），节点天然 = 格子。
- 真正吃时间的 4 道：`0127`（节点=单词）、`0752`（节点=4 位字符串）、`0909`（节点=1~n² + redirect）、`1293`（节点=(i,j,k) 三元组）。
- **这 4 道花的总时间 ≈ 其余 10 道之和。** 下一阶段练习应该刷隐式图建模题，而不是再练网格 BFS 模板。一道题的难度几乎完全由“把题面变成 (节点, 边, 边权, 起点, 终点) 五元组”这一步决定，五元组定了之后模板都一样。

### 4. 模板已经收敛，但有三处风格债没回收
比对 15 份代码看得很清楚——主线模板是：`size = q.size()` 外层循环 + dirs 数组 for-each + `int[2]` 状态（≥ 9 道用这套）。剩下三处是早期写法残留：
- **`0994`**：用 `queueCurr / queueNext` 双队列交换，不一致。
- **`0542 / 0695`**：四方向 unroll 成 4 个 if，没用 dirs 数组。
- **`0934`**：原地 `-1 / -2 / 2` 多档 sentinel，README 自己已经批评过。

复刷这三题时**优先做的不是重新求解，而是回去把风格统一到现行模板**——回收风格债比再做一遍更有价值。

### 5. `0934` 暴露了一个未命名的复合范式：连通分量 + 多源最短路
README 把它当“两阶段图搜索”一笔带过，但模式本身值得显式命名：
> **先 DFS/BFS 染色识别连通分量 → 把整个连通分量作为多源 BFS 起点。**

所有“两个区域之间的最短距离 / 区域到边界的距离”题都吃这一套（`1162` 也是它的简化版——多源不再需要先染色，因为多源点天然给定）。把它当成一个独立模式记住，下次遇到“先识别区域再算距离”的题面，直接套。

### 6. 没出现的模式，比出现的更重要
本轮 15 题里没出现的：
- **双向 BFS**：`0127 / 0752` 都是经典适用场景，本轮都用了单向。
- **0-1 BFS / Dijkstra**：`1293` 若把“消障”看作边权 0/1，就是 0-1 BFS 板子题。
- **A***：`1091 / 1293 / 1926` 都能加曼哈顿启发式。

这是下一轮的真实空白点。再刷 10 道网格 BFS 的价值低于补这三块。

### 7. “低级错误”其实是同一件事：建图入口 checklist 缺失
`127`（忘加 beginWord / 忘标 visited / endWord 不在表里）、`909`（redirect 后才能判终点）、`1091`（先 poll 后取 size）——本轮所有“低级错误”都能归到同一份起手 5 问：
1. 起点是否在节点集合中？要不要手动加？
2. 终点是否在节点集合中？要不要先判存在再 BFS？
3. 起点入队时 visited 是否同步标记？
4. 提前判终点的位置：邻居枚举后？还是 redirect 后？
5. 分层 BFS 顺序：先 `size = q.size()` 再 `poll()`。

写 BFS 前过一遍这 5 条，比事后调试快 10 分钟。这一条是“最有 ROI 的肌肉记忆”。

## 一、第一直觉：题面 → 模型

### 1. 看到“最短 / 最少步数”立刻切 BFS，不要 DFS
- 无权图最短路一律 BFS，DFS 写下去都会变绕。
- 代表题：`127`（一开始误选 DFS 写到一半才推翻）、`542`（一开始用 DFS + memo 翻车）、`909`、`1091`、`1293`。
- `542` 的教训最重要：DFS+memo 之所以不成立，是因为节点之间互相依赖、依赖项的最短距离尚未收敛时就被当前节点提前写入。BFS 队列天然保证按距离递增扩展，不存在“依赖未稳定”问题。

### 2. 看到题目就先问“这是不是隐式图”
- 不是只有显式邻接表才叫图。本轮多道题都是 implicit graph：
  - `127`：单词 = 节点，差一位 = 边，用 `*` 通配 pattern 建中间分组再连边。
  - `909`：编号 `1~n²` = 节点，掷骰子 = 6 条出边，蛇/梯 = 强制 redirect。
  - `1293`：状态 = `(i, j, 已消耗障碍数)`，资源维度并入节点。
- 网格题（`542 / 695 / 934 / 1091 / 1162 / 1293`）本质也是隐式图，dirs 数组就是邻接表。

### 3. 一眼识别多源 / 反向 BFS
- “从所有 X 同时向外扩散” → 把所有 X 一次性入队，做 multi-source BFS。
  - `542`：所有 `0` 入队。
  - `1162`：所有陆地入队。
  - `934`：整座第一岛全部入队（不必显式找边缘，内部节点周围全是已访问，自然只有边缘真正扩散）。
- “每个点能不能流到目标区域”不好正向判断时，反向从目标出发搜：
  - `417`：分别从 Pacific / Atlantic 边界反向 BFS，取交集。

## 二、模板与肌肉记忆

### 1. 分层 BFS 固定顺序（`0994 / 1091`）
```java
while (!q.isEmpty()) {
    int size = q.size();          // 先固定本层大小
    for (int i = 0; i < size; i++) {
        int[] curr = q.poll();    // 再 poll
        ...
    }
    step++;
}
```
- `1091` 卡过：先 `poll()` 再读 `queue.size()`，导致层边界全错。顺序必须形成肌肉记忆，不靠临场推理。

### 2. 方向数组（`1162`）
```java
int[][] dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
```
- 消除四份重复的边界检查代码。八方向题（`1091`）同理扩展。

### 3. BFS 与 DFS 的判定方向相反（`0695`）
- BFS：在**入队**时判定合法（越界 / 已访问 / 障碍直接不入队）。
- DFS：在**进入函数**后判定非法并立即 return。
- 写错方向的典型症状：BFS 队列里塞进越界点再 poll 出来才处理，或 DFS 先递归再判越界导致栈溢出 / `ArrayIndexOutOfBounds`。

### 4. 原地修改当 visited（`0934 / 1091`）
- 可以省 visited 数组，但**状态语义必须简单**。
- `0934` 反例：自己引入了 `-1 / -2` 标记“边缘 / 已访问海水”等多种状态，调试成本远高于额外开一个 visited。
- 推荐最多三档：`0 = 未访问海`、`1 = 未访问陆`、`2 = 已访问 / 第一岛`。

## 三、状态设计：visited 不只是 boolean

### 1. 资源 / 代价维度并入状态（`1293`）
- 带资源限制的最短路（最多消除 k 个障碍），位置相同但资源消耗不同就是不同状态。
- `visited[i][j]` 改为“到达 (i,j) 时的最小障碍消耗”；新状态消耗 ≥ 历史最优才剪枝。
- 同位置下，资源消耗更少的状态支配资源消耗更多的状态。

### 2. 双数组取交集（`0417`）
- `toPO[i][j]` / `toAO[i][j]` 各跑一遍反向 BFS，最后扫一遍取交。
- 比“一个数组用 `1 / -1 / 0` 编码两种可达性”自然得多。

## 四、本轮反复踩到的坑

### 1. 复制粘贴漏改对应变量（`0417`）
- 初始化 Atlantic 边界时复制了 Pacific 的循环，只改了队列名，没改 `toPO → toAO`，调了 10 分钟。
- 教训：抽出公共方法（如 `bfs(queue, visited)`），不要靠复制粘贴扩展，避免“改了一半”。

### 2. 终点判定时机错位（`0909`）
- 错：`if (next == end)` —— 落点本身不是终点，但落点上有梯子能跳到终点的情况会被漏掉。
- 对：先做 redirect 拿到 `dest`，再判 `dest == end`。
- 普遍化：**有强制跳转 / 后处理的题，终点判定必须放在跳转之后**。

### 3. 过早启发式剪枝（`0909`）
- 想“只保留跳转节点 / 只保留 `curr + 6`”，但当前看似普通的格子可能连到更优的梯子。
- BFS 中：**完整枚举合法邻居 + visited 去重**几乎永远比手工筛选稳。

### 4. 写代码前不先抽框架（`0417`）
- 直接顺着思路写出两份几乎一样的 `while` 循环再重构，浪费时间。
- 思路定后先问自己：需要几个状态数组 / 几次 BFS / 哪些能抽公共方法。

### 5. 低级遗漏（`0127`）
- BFS 忘标 visited → 死循环。
- 建图时忘把起点（`beginWord`）加进去（起点不在 wordList 里）。
- 终点（`endWord`）不一定在 wordList 里，要额外判定。
- 共通点：**“起点 / 终点不一定在初始集合中”是建图类题的固定边界 checklist。**

### 6. 编号 ↔ 坐标映射（`0909`）
- 先举例（`1 → (n-1, 0)`、`n+1 → (n-2, n-1)` ...）验证规律，再写公式，不要硬推。

### 7. 字符串操作不熟（`0127`）
- `substring` + `*` 拼接调试很慢；pattern 必须保留“变化发生在哪一位”：
  - 错：`s.substring(0, i) + s.substring(i + 1)` —— `tail` 和 `talk` 会被错误归到同组。
  - 对：`s.substring(0, i) + "*" + s.substring(i + 1)`。

## 五、面试讲述要点

- “这是个无权图最短路 → 我用 BFS。”
- “节点不是显式的，我把 X 映射成节点，把 Y 映射成边，这是 implicit graph。”
- “正向不好判断时，我从目标反向搜。”
- “BFS 第一次到达终点时的层数就是答案，正确性来自队列按距离递增扩展的不变量。”
- “visited 不一定是 boolean——当存在资源 / 代价维度时，记录最优代价才是正确的剪枝。”
