# 前端功能新增清单（供 CC 实现）

日期：2026-07-18 ｜ 依据：insight/midterm-review-2026-07.md 第六节、ROADMAP.md（R19 / Review 调度 / UNSEEN 日志）、EXECUTION.md（起手 Checklist / 支线制度）

## 现状（已有功能，勿动）

基于 ROADMAP 识别 Round 专题；每日推送一题（可选难度）；LC 链接直达；Create Note 粘贴笔记与代码；标记状态（x / x-r / r）。

## 总体约束

1. **ROADMAP.md 是唯一事实源**。所有状态变更（标记升级、日志追加）直接落盘到 ROADMAP.md 对应行，不引入独立数据库存状态副本；前端自身最多缓存解析结果。
2. **旧笔记与代码只读**。任何 review / 重做产生的内容一律新增文件，不覆盖、不修改题目目录下已有的 README.md 与 Solution.java。
3. R19 区块已重构，解析时注意三个子分组：`## 新轮 [r]`、`## 新轮 [x/r]`、`## 旧轮存量`；其中 146 一行无复选框（由 MOCK 自然重考），跳过即可。

## P0-1 Review 专区（独立模块，替换现有 review 模式）

现有 review 模式两个问题：按专题组织（应按题推送）；直接打开并修改旧代码旧笔记（应新增）。重构为：

- **数据源**：解析 ROADMAP R19 区块的全部未完成条目（`- [ ]`），而非按专题目录扫描。
- **推送顺序**：先 `[r]` 后 `[x/r]`；`[r]` 内部按 ROADMAP "Review 调度建议"中的显式优先序（460 → 321/2104/862 → 424 → 54/73/220/324 → 316/752/1203 → 721/1489）。
- **条目展示**：题号、标题、来源轮次、难度、以及条目行内附带的**重做标准**文本（如 862 的"主流单调队列 O(n) 版 + 讲清与支配关系推导的等价性"），推送时必须显示。
- **入口**：与每日新题并列的独立 Tab / 模块，不再挂在专题下。

## P0-2 Review 产物版本化（新增而非覆盖）

- 每次 review 在题目目录下新增：`reviews/YYYY-MM-DD.md`（笔记）+ `reviews/Solution_YYYY_MM_DD.java`（代码）。题目目录不存在 reviews/ 时自动创建。
- Create Note 界面在 review 场景下写入上述新路径；原 README.md / Solution.java 以只读方式并排展示，方便对照旧版找改进点（ROADMAP 规则："对比旧版找改进点"）。
- review 笔记**不预填模板**，创建为空文件后自由书写。条目上的重做标准在界面上展示供参考，不写入文件。（固定模板已试过一次并证伪：2104 的空模板只剩三个空标题，反而抬高了动笔门槛。）

## P0-3 Review 结果落盘（标记升级）

- review 完成后提供两个结论按钮：**通过**（该行升级为 `- [x] ...`，保留原 [r]/[x/r] 来源注记）／**仍有问题**（保持原标记，追加一次重做记录）。
- 同一题在原轮次区块中的标记行（如 R2 的 `- [r] 460. LFU Cache`）**不改动**，只动 R19 区块——避免双处状态不一致；如实现成本低，可同时在原轮次行尾追加 `（R19 已通过 YYYY-MM-DD）` 注记。

## P1-1 每日推送感知 review 债务

- 还债期节奏（ROADMAP 规则）：**每推送 2-3 道新题，自动插入 1 道 [r] 作为当日小菜**（与新题并列展示，标注"review · 限时 30min"）。
- 比例可配置（默认 3:1），[r] 清零后自动降回"每 5-7 道新题穿插 1 道 [x/r]"。
- 首页显示债务余额：`[r] 剩余 n 道 / [x/r] 剩余 m 道`，以及"R9 启动前 [r] 清零"的目标提示。

## P1-2 UNSEEN 模块

- 独立入口：手动登记一场 UNSEEN（来源：周赛 / 字节 tag / 腾讯 tag，题号，结果，暴露盲区 → 反馈 Round）。
- 提交后向 ROADMAP 的 `## UNSEEN 执行日志` 表格**追加一行**（markdown 表格行拼接即可）。
- 距上次 UNSEEN 超过 14 天时，首页出现提醒横幅（"无日志视同未执行"）。

## P1-3 计时器（2026-08-20 撤销：不再实现，已有实现应移除）

原设计为按 Phase 内置倒计时并自动把耗时写入笔记头部。撤销原因：LeetCode 自身的计时以“打开题目”为起点、以 AC 为终点，恰好等于需要记录的量；工具侧另起计时既冗余，实测又全盘失真。

R7-R8 期间自动写入的 10 条耗时记录经本人核对**全部与实际不符**（记录值含 `<1min` 四条、`1155min` 与 `210min` 各一条；实际均在 40min 以内，多数为 10-30min，这也是当时敢于标记 `[x]` 的依据）。10 条已在各题笔记中统一改为“未记录（计时器数据作废）”，不保留任何工具生成的数值。

替代方案：

- 耗时来源改为 LeetCode 自带计时，创建笔记时由使用者手工填入头部 `耗时：Xmin` 一行，格式不变。
- 工具不做倒计时、不做超时提示。各 Phase 时限标准（AUDIT 25/35/50min、MOCK 与 UNSEEN 45min、Review 小菜 30min、NEW 不限时）保留在 EXECUTION.md 与 ROADMAP.md 中作为执行标准，不进工具。

## P2-1 起手 Checklist 卡片

NEW / MOCK 开题界面展示 EXECUTION.md 中的四行 Checklist（读题圈选择约束与数据范围 / 动手前问状态能否降级与变体成本 / 单调结构先论证相等归属 / 卡边界画图写等式）。直接从 EXECUTION.md 解析或硬编码同步均可，展示即可，无需交互。

## P2-2 每周默写提醒

- 每周首次打开时提醒："本周 API 默写未完成"，链接到 insight/java-api-fluency.md。
- 完成后登记一行（日期 / 分区 / 错误数），追加到 java-api-fluency.md 尾部日志区（若该文件尚无日志表，追加时自动创建 `## 默写日志` 表头）。

## P2-3 统计面板

- 速率曲线：题/天（可从笔记文件的创建日期或 git log 推得，取实现成本低者）。
- review 债务余额趋势、距 2027-02-01 倒计时。
