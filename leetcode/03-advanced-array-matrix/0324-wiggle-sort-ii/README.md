# 324. Wiggle Sort II

## 我的思考
一开始很快想到排序解法：

先排序，然后把数组分成小半段和大半段，再从两段末尾倒序交叉放入原数组。

小半段放偶数位，大半段放奇数位，可以避免相同元素集中在一起。

后来继续思考进阶的 O(n) 时间复杂度。排序并不是本质，真正需要的是把数组按中位数划分成两部分：

- 小半段：`<= median`
- 大半段：`>= median`

两段内部是否有序并不影响最终交叉放置的正确性。

因此可以用 quickselect 找到中位数，并通过三向 partition 得到类似：

`[lessThanMid][mid][largeThanMid]`

的结构。之后仍然复用排序版的倒序交叉插入逻辑。

## 卡点
一开始的 `O(n log n) / O(n)` 排序解法很快。

主要卡在进阶部分：

- 没有第一时间想到用三向 partition 处理中位数和大量重复元素；
- 三向 partition 很久没写过，实现花了较多时间；
- 快排相关模板不够熟，尤其是 `[< pivot][= pivot][> pivot]` 的边界维护。

## 关键点
排序版的核心不是“有序”，而是：

- 小半段整体不大于中位数；
- 大半段整体不小于中位数；
- 从两段末尾倒序交叉取值。

因此 quickselect + 三向 partition 后，即使两段内部无序，也可以复用同样的插入逻辑。

最终交叉方式：

- 偶数位取小半段末尾；
- 奇数位取大半段末尾。

## 主流解对照
当前版本完成了平均 O(n) 时间，但仍使用了额外数组，因此空间复杂度是 O(n)。

更进一步的 O(1) 空间版本需要使用 virtual index mapping + 原地三向 partition，本次先暂停，没有继续展开。

## 复杂度
时间复杂度：平均 O(n)，当前 pivot 选择下最坏可能退化为 O(n^2)

空间复杂度：O(n)

## 注意
后续复刷重点不是排序版，而是：

- 三向 partition 模板；
- quickselect 找中位数；
- virtual index mapping 的 O(1) 空间版本。
