# 57. Insert Interval

## 我的思考
题目给出的 intervals 已经按 start 升序排列，并且区间之间互不重叠。插入 newInterval 后，只需要处理它和原有区间的相对位置关系。

一开始想到可以对 newInterval 的 start 和 end 分别二分查找插入位置，定位受影响区间。但最终答案仍然需要遍历构造，整体复杂度还是 O(n)，二分不会改变总复杂度，反而会增加边界处理成本。

因此改用线性扫描。整体分为三段：

1. 完全在 newInterval 左边的区间，直接加入答案；
2. 与 newInterval 有重叠的区间，合并进 newInterval；
3. 完全在 newInterval 右边的区间，直接加入答案。

## 卡点
一开始因为感觉题目过于简单，怀疑是否需要更复杂的处理，比如二分定位端点、预处理答案数组长度等，浪费了一些时间。

第一版代码把左边界、右边界、包含关系、插入时机混在一轮循环里判断，控制流比较乱，不利于证明正确性。

## 关键点
区间题优先按相对位置分类：

- `interval[1] < newInterval[0]`：当前区间在新区间左边；
- `interval[0] <= newInterval[1]`：当前区间和新区间有重叠，需要合并；
- 剩余区间都在新区间右边，直接加入答案。

合并时更新：

`newInterval[0] = min(newInterval[0], interval[0])`

`newInterval[1] = max(newInterval[1], interval[1])`

## 主流解对照
主流解法就是三段线性扫描。二分查找虽然可以更快定位受影响区间，但由于最终必须构造返回数组，总体复杂度仍然是 O(n)，代码复杂度反而更高。

## 复杂度
时间复杂度：O(n)

空间复杂度：O(n)，主要来自返回结果；不考虑返回结果时，额外空间为 O(1) 到 O(n)，取决于是否把 List 视为构造返回值的一部分。

## 注意
Java 中返回 `int[][]` 且答案长度不定时，可以先用 `List<int[]>` 收集，最后转换：

`return ans.toArray(new int[ans.size()][]);`
