# 41. First Missing Positive

## 我的思考
前 6min 没有明显思路，看到标签“哈希”后想到可以把数组本身当哈希表。

目标是找第一个缺失的正整数。对于长度为 `n` 的数组，只需要关心 `[1, n]` 范围内的数，因为如果这些数都存在，答案就是 `n + 1`。

核心映射：

`num = x -> index = x - 1`

也就是把值 `x` 放到 `nums[x - 1]` 的位置上。最终如果 `nums[i] == i + 1`，说明 `i + 1` 存在；否则说明 `i + 1` 缺失。

## 卡点
主要卡在如何在 `O(n)` 时间、`O(1)` 额外空间下完成哈希记录。

想到原地哈希后，主要时间花在交换条件和下标映射上。

## 关键点
数组本身可以作为哈希槽：

- 只处理 `1 <= nums[i] <= n` 的数；
- 数字 `x` 应该放到下标 `x - 1`；
- 如果目标位置已经是 `x`，说明有重复，不能继续交换，否则会死循环。

交换条件中需要避免重复值导致死循环：

`nums[nums[i] - 1] != nums[i]`

我更偏好把非法位置置为 `0`，让最终数组语义更清晰：

- `nums[i] == i + 1`：合法，表示 `i + 1` 存在；
- `nums[i] == 0`：非法或缺失。

## 复杂度
时间复杂度：O(n)

空间复杂度：O(1)

## 注意
看到以下条件时，要优先联想到原地哈希 / index mapping：

- 要求 O(n)；
- 要求 O(1) 额外空间；
- 元素值范围和数组下标存在映射关系；
- 问缺失、重复、出现情况。
