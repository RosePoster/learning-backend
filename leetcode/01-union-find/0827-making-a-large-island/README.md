# 827. 最大人工岛

## 我的思考

本题可以先用 Union-Find 处理所有已有陆地连通分量，并维护每个连通分量的面积。水格子的面积统一设为 0，这样后续统计答案时，不需要再额外区分相邻格子是陆地还是水，只需要查询相邻 component 的 size。

第一遍遍历 grid，遇到 0 就将对应节点的 size 设为 0；遇到 1 就只和上方、左方已经遍历过的陆地进行 union。

第二遍枚举每个 0，假设把它翻转为 1，则新岛面积为 1 加上上下左右不同连通分量的面积。用 Set<Integer> roots 对四周 root 去重，避免同一个岛从多个方向被重复累加。

## 卡点

debug 主要出现在方向遍历上。一开始使用：

int[] dirs = new int[]{-n, n, -1, 1}

直接对一维 id 做加减，并用 id >= 0 && id < n * n 判断是否合法。但这种判断会导致左右方向跨行。例如某一行最左侧格子的左边，会被错误映射到上一行最右侧格子。

二维 grid 中，如果用一维 id offset，左右方向必须额外判断列边界；只判断 id 范围不足够。最终改为使用二维方向数组：

int[][] dirs = {{-1,0}, {1,0}, {0,-1}, {0,1}}

通过 nI、nJ 判断边界，更安全。

## 关键点

本题的核心是先预处理每个岛屿连通分量的面积，再枚举每个 0 作为翻转候选。

枚举某个 0 时，不需要手动判断上下左右的连通分量之间是否彼此联通。只需要将四个方向的 root 放入 Set<Integer> roots 中去重，再累加每个 root 对应的 size 即可。

Set 去重解决了“同一个岛从多个方向接触当前 0”导致的重复累加问题。

水格子的 size 被提前设为 0，因此即使相邻水格子的 root 被加入 roots，也不会影响面积结果。这属于预处理阶段对 component summary 的统一化：UF 阶段负责处理好每个格子的面积贡献，答案阶段只负责查 root、去重、累加面积并更新最大值。

## 复杂度

时间：O(n² α(n²))，第一遍 union 陆地，第二遍枚举每个 0 并检查四个方向。

空间：O(n²)，主要来自 Union-Find 的 parent 和 size 数组。

## 注意

二维 grid 中，不能只用 id >= 0 && id < n * n 判断一维偏移是否合法。上下方向可以用 id ± n，但左右方向必须额外判断是否跨行。

枚举翻转 0 时，用 Set<Integer> roots 去重即可，不需要额外判断上下左右连通分量之间是否联通。只要 root 相同，Set 会自动去重；root 不同，则说明是不同 component，可以安全累加。
