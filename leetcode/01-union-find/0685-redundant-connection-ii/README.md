# 685. Redundant Connection II

## 我的思考

基于：“输入是否一定保证来自一棵合法有根树加一条附加边。“的前提推导

首先发现结果可能有环，也可能没有环。有环时需要拆环；有双入边时，只能在这个双入节点的两条入边里选择删除边。

最初写成动态判断，把 case1 和 case2 揉在一起：遍历过程中一旦出现环就认为是 case1，一旦出现双入节点就记录为 case2，最后再判断删除哪一条边。后来发现这样会出错，因为存在双入边和环同时出现的情况。此时不能从环里随意删除边，答案只能在双入节点的两条入边里选择。如果环的闭合比双入边判断更早触发，代码可能错误地删除闭合环的边，导致保留双入节点，最终仍然不是合法有根树。

观察到这一点后，改成提前判断是否存在双入节点。最终代码先扫描所有边，找到是否存在某个节点有两条入边。如果不存在双入节点，则顺序 union，遇到第一条 union 失败的边直接返回；如果存在双入节点，则先跳过这两条候选入边，union 其余边，最后测试第一条候选边是否可以加入，从而判断应该删除哪一条候选边。

这里有一个隐含invariant：case2 两条待选边可能都是可以删除的边，此时按题目要求应该删除后出现的，先测试candidates.get(0)保证删除的是后出现的candidates.get(1)。

节点编号从 1 到 n，而不是从 0 到 n - 1，因此 parent 数组多开一位，0 号下标不使用。这样可以直接用 edge 中的节点编号作为数组下标，避免反复加减 1。

## 卡点

主要卡点在于一开始把环和双入边混合在线处理，没有先确定是否存在双入节点。这样会忽略“双入边和环可以同时存在”的情况。

当存在双入节点时，答案空间已经被限制在该节点的两条入边中。此时即使图中出现环，也不能简单删除环中最后出现的边，因为删除其他边无法解决双入节点的入度问题。

另一个耗时点是最后犹豫提前判断双入节点是否可行。最终确认：提前扫描入度是正确的，因为题目保证输入来自合法有根树加一条附加边，一个节点最多只会出现两条入边。

## 关键点

题目给定的数据结构可以理解为：一棵合法有根树加上一条额外有向边。基于这个前提，只会出现两类核心结构：

case1：不存在双入节点。  
此时所有节点入度正常，额外边一定制造了一个有向环。由于没有双入节点，删除环内任意一条边都能恢复合法树。题目要求如果有多个答案，返回输入中最后出现的边，因此顺序遍历时，第一条导致 union 失败的边就是环中最后出现的边，直接返回即可。

case2：存在双入节点。  
此时某个节点有两条入边，答案只能在这两条入边中选择。因为删除任意其他边都无法解决该节点入度为 2 的问题。处理方式是先找出这两条候选边，跳过它们，对其余边执行 union。之后测试第一条候选边：如果加入它不会形成环，说明第一条可以保留，应该删除第二条；如果加入它会形成环，说明第一条不能保留，应该删除第一条。

Union-Find 在这题中主要用于判断底层连通结构是否成环。方向约束不是由 Union-Find 单独解决的，而是通过提前扫描入度异常来处理。因此不能把这题当成普通无向冗余边问题直接裸跑 Union-Find。

更准确地说：先用入度扫描处理 rooted directed tree 的方向合法性，再用 Union-Find 判断候选边是否会破坏底层树结构。

## 主流解对照

主流做法是先扫描每个节点的入度，判断是否存在双入节点。若不存在双入节点，则使用 Union-Find 找到导致环的最后一条边；若存在双入节点，则记录两条候选入边，临时跳过其中一条或两条进行 Union-Find 检测，根据是否仍然成环决定删除第一条还是第二条候选边。用户解法与主流解等价，是“先锁定双入候选，再用 Union-Find 测试候选边”的变体。

## 复杂度

时间：O(n α(n))，其中 n 为边数，也等于节点数。扫描入度为 O(n)，Union-Find 操作为近似常数。

空间：O(n)，用于 parent 数组、入度标记数组和候选边列表。

## 注意

这题不能把“出现环”和“出现双入边”在线混在一起判断。只要存在双入节点，答案一定在该节点的两条入边中，不能从环里随意删除边。

有向树加一条边的问题，优先检查入度异常，再判断环。入度异常属于方向约束，环属于底层连通结构约束，二者职责不同。

Union-Find 在本题中不是完整地判断有向树合法性，而是在入度条件被单独处理后，用来判断候选边是否导致底层环。

变量命名上，hasFrom 和 doubleFromNode 不够准确。更合适的命名是 hasParent 和 nodeWithTwoParents。因为记录的是某个节点是否已经有入边，而不是 from 节点。

parent 数组多开一位是合理的 1-based 映射技巧，但变量名中不要把数组长度和真实节点数量混淆。可以使用 nodeCount = edges.length，UnionFind(nodeCount + 1)，这样解释更清楚。
