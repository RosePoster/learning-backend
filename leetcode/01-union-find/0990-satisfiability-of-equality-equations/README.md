# 990. Satisfiability of Equality Equations

## 我的思考
使用并查集处理。先遍历所有等式 `==`，将相等变量合并到同一个集合；再遍历所有不等式 `!=`，如果不等式两侧变量已经属于同一个集合，则说明存在矛盾，返回 `false`。

一开始想过使用两个并查集：一个 `eqUF` 维护相等关系，一个 `unEqUF` 维护不等关系。处理 `==` 时先查 `unEqUF`，处理 `!=` 时先查 `eqUF`。但这个思路有问题。

例如：

    a == b
    b != c
    a == c

处理到 `a == c` 时，当前已知：

    eqUf: a == b
    unEqUf: b != c

直接查 `unEqUf` 时查不到 `a` 和 `c` 的不等关系，因此无法发现矛盾。除非先在 `eqUf` 中找到 `a`、`c` 的根，再去 `unEqUf` 中查两个根之间的不等关系。但这样又要求不等关系中记录的根必须稳定，例如固定在 `b` 这个出现过不等关系的节点上；而普通并查集合并时 root 可能变化，这会导致关系维护复杂。

因此本题不适合用两个普通并查集处理。相等关系是等价关系，可以用并查集维护；不等关系不是等价关系，不能直接用并查集表示。

## 卡点
- 并查集实现不熟练，`union` 一开始写成：

        parent[j] = find(parent[j]);
        parent[parent[j]] = i;

  这个写法会直接把 root 挂到一个未确定为 root 的节点下。如果某个 root 被挂到自己子节点下面，就会形成环，导致 `find` 无限递归。

- 正确写法必须先分别找到两个节点的 root，再将一个 root 挂到另一个 root 下：

        int rootI = find(i);
        int rootJ = find(j);
        if (rootI != rootJ) {
            parent[rootJ] = rootI;
        }

- 一开始尝试用两个并查集分别维护相等和不等关系，但不等关系不是等价关系，不能直接压成集合。

## 关键点
- 并查集适合维护等价关系；`==` 具有传递性，可以合并集合。
- `!=` 不具有跨并查集传递性，不能用普通并查集维护。
- `union` 必须 root-to-root，不能把 root 挂到非 root 节点下。
- 如果要求流式处理，则需要在并查集之外维护等价类之间的不等约束；本题离线两遍处理更简单。

## 主流解对照
LeetCode 主流做法是两遍扫描：第一遍用并查集合并所有等式，第二遍检查所有不等式是否落在同一集合。当前解法与主流解法等价；最开始的双并查集思路属于错误建模，因为不等关系不能作为等价集合维护。

## 复杂度
- 时间：`O(n * α(26))`，其中 `n` 为 equations 数量；由于变量只有 26 个，也可视为 `O(n)`。
- 空间：`O(1)`，并查集数组大小固定为 26。

## 注意
- 默写标准 `find / union`。
- 要明确区分：相等关系可以合并成集合；不等关系只能作为集合之间的约束边，不能直接用普通并查集表示。
