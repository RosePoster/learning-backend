# 839. 相似字符串组

## 我的思考

这题可以直接建模为连通分量问题。每个字符串是一个节点，如果两个字符串相似，就在它们之间建立连接。最终答案就是相似字符串图中的连通分量数量。

第一反应是使用 Union-Find。问题转化为：如何判断一个新字符串是否属于某个已有集合。

一开始尝试从集合表达能力入手，考虑维护每个集合可表示的通配符模式。例如 `star` 和 `tsar` 相似后，集合似乎可以表达 `..ar`，进一步判断哪些字符串可以加入。但这个方向会涉及通配符集合的传递扩展，难以简单维护。相似关系本身是传递闭包，强行维护集合的生成模式会把问题复杂化。

随后回到直接做法：两两比较字符串，如果不同字符位置数量小于等于 2，则两者相似，执行 union。由于 `n <= 300`，`m <= 300`，复杂度 `O(n²m)` 可以接受。

最终选择暴力两两比较 + Union-Find。

## 卡点

主要卡点来自题目 Hard 标签和暴力做法之间的冲突。

这题第一眼就能想到两两比较，但因为它是 Hard，且暴力代码很短，容易怀疑是否存在必须使用的更优解，从而转向通配符、交换变体等复杂方向。

## 关键点

相似字符串组本质是相似关系的传递闭包，因此可以用 Union-Find 统计连通分量。

两个字符串相似的判断：

- 若两个字符串完全相同，应视为同组。
- 若两个字符串只有两个位置不同，可以通过交换一次变成相同。
- 在题目保证字符串互为字母异位词的前提下，不同位置数量为 1 的情况不会出现。

实现时写成 `diffs > 2` 时提前返回 false。

两两比较前先判断两个下标是否已经属于同一连通分量，如果已经在同一组，则跳过相似性比较，减少重复检查。

## 复杂度

时间：O(n²m)，其中 n 是字符串数量，m 是字符串长度。提前判断同组和 `diffs > 2` 提前退出可以降低平均耗时。

空间：O(n)，用于 Union-Find 的 parent、size 数组。

## 注意

Hard 标签不能替代复杂度判断。若约束允许，代码短、证明直接、实现风险低的暴力解应优先考虑。

本题的关键决策不是寻找复杂优化，而是相信 `O(n²m)` 在数据范围内可行。更复杂的通配符或交换变体方案可能有理论探索价值，但会显著增加实现和证明成本，不适合作为本题主解。
