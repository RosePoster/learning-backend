# 316. Remove Duplicate Letters

## 思考
本题最终使用栈维护当前构造出的答案前缀，并用 `inStack` 保证每个字符只进入答案一次，
用 `lastIndex` 判断某个字符未来是否还会出现。

遍历字符串时，如果当前字符已经在栈中，则跳过。否则尝试将当前字符加入答案。在加入前，若当前字符比栈顶字符更小，并且栈顶字符后面还会再次出现，则可以弹出栈顶，使更小的字符尽量靠前，从而得到更小的字典序。

本题耗时较长，主要不是代码复杂，而是对这类“贪心构造栈”的把握还不够自然。脑子里反复输入“栈、去重、字典序、未来是否还会出现”几个条件，但一开始没有迅速命中稳定模型。

## 卡点
- 对栈的理解还停留在普通栈/单调栈层面，对“用栈构造最优答案前缀”的模型不够熟。
- 一开始反复理解弹栈条件，但没有迅速把三个条件统一起来：
  - 当前字符更小；
  - 栈顶字符未来还会出现；
  - 当前字符不在栈中。
- 这类题是“当前字符能否让已构造前缀更优”的贪心问题。
-  `lastIndex` 一开始没有想到，以后可以注意，可以提前遍历一遍取信息。
- 最终建模是：栈里保存的就是答案（的逆序）。

## 关键点
- 栈表示当前已构造出的最优答案前缀。
- `inStack` 用于保证每个字符只出现一次。
- `lastIndex` 用于判断弹出某个字符后，未来是否还能补回来。
- 弹栈条件：`当前字符 < 栈顶字符 && 栈顶字符后面还会出现`。
- 这类题的核心不是“栈操作”，而是“在不破坏可行性的前提下，让更小字符尽量靠前”。

## 复杂度
- 时间：`O(n)`
- 空间：`O(1)`，字符集固定为 26。
